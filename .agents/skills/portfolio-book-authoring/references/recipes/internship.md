# Internshipの本

対象は1社でのインターン経験。`books/internship/<id>/`に保存する。共通の制作・表紙・検証・公開手順はSKILL.mdに従い、このレシピは質問と原稿の内容を担当する。2026-11-07に本人が下記6章を承認した。

## ヒアリングの焦点

既存資料とintakeを読み、未回答の点だけ1問ずつ聞く。最初の例：「どの会社で、いつ頃、どんな役割で参加しましたか？」

- 会社の紹介、期間・職種・参加理由、本人が一番伝えたい経験は何か。
- 所属チームと本人の担当・責任範囲は何か。チーム全体と本人の仕事を分ける。
- 実際に何をしたか。代表的な業務・成果物を1つ選び、進め方を具体的に聞く。
- 難しかった点と、本人が選んだ方法・理由は何か。協働やフィードバックをどう活かしたか。
- 納品・採用・改善など確認できた結果はあるか。本人の貢献と会社全体の成果を分ける。
- できるようになったこと、苦労や学び、今後に活かすことは何か。
- 画像・会社名・業務詳細・実績・URLのうち、紹介してよい範囲を確認する。既に許可済みの事項は聞き直さない。

## 紙面への対応

| 章／ページid | 掲載する内容 |
|---|---|
| 01 インターンについて／about | 会社名・概要・在籍期間・職種、参加理由 |
| 02 担当範囲／responsibilities | 担当対象・責任・チームとの役割分担 |
| 03 実際に行ったこと／work | 具体的業務・成果物・進め方、使用ツールの用途 |
| 04 工夫・判断／decisions | 課題に対する本人の選択、理由、協働・改善 |
| 05 成果／outcome | 提出物・確認された貢献・反応、測定結果があれば条件 |
| 06 振り返り／reflection | 学び・難しかったこと・今後に活かすこと |

目次はcontents。上表の6章の名前・順序・ページidは全社で固定する。情報が未提供の章も目次とページを残し、本文は空欄のままでよい。章を省略・繰り上げたり、架空の実績や「準備中」の文を足したりしない。足りない内容はintakeに記録し、その章に沿って後からヒアリングする。技術は独立の必須章を増やさず、実際の業務や判断に結びつける。関連作品の本がある場合は重複説明を絞り、実装されていない本間リンクを作らない。公開できない業務は抽象化した本人確認済みの説明に留める。会社全体の成果を本人の実績にせず、掲載許可不明の社内資料は原稿へ取り込まない。

勤務期間は本文だけでなく表紙にも必ず掲載する。開始年月・終了年月／現在は本人の回答に従い、表紙に「頃」は付けない。他カテゴリと同じく表紙右下へ小さく、`2026.06–現在`のように期間を表示し、book.ts.details.periodを正本とする。修正回答が来たら表紙と本文を同時に更新し、旧サイトの年月へ戻さない。
