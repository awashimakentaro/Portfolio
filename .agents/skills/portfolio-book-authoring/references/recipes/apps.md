# Appsの本

対象は利用者が操作するアプリ・Webサービス。`books/apps/<id>/`に保存する。共通の制作・表紙・検証・公開手順はSKILL.mdに従い、このレシピは質問と原稿の内容を担当する。

## ヒアリングの焦点

既存資料とintakeを読み、未回答の点だけ1問ずつ聞く。最初の例：「どんな人が、何をできるようになるアプリですか？」

- どの場面の困りごとを解決したかったか。従来のやり方と目標は何か。
- 代表的な機能を使うと、入力→操作→結果はどうつながるか。紹介したい操作を1つ聞く。
- 個人／チーム制作、期間、本人の担当。実装済みと今後の予定を分ける。
- 画面・情報設計・実装で何を選び、なぜ選んだか。試して変えた例はあるか。
- 誰がどう試し、何が分かり、どこを変えたか。利用者テストと本人の動作確認を分ける。
- 確認できた成果、学び、今後の改善。技術・ツールは用途と選定理由を聞く。

## 紙面への対応

| 章／ページid | 掲載する内容 |
|---|---|
| 01 作品について／about | 正式名・一言概要・利用者・制作動機・期間・担当、実画像と実在リンク |
| 02 課題・背景・目標／context | 利用場面と従来の課題、解決したい状態 |
| 03 制作プロセス／process | 設計から実装まで、代表的な操作と判断理由 |
| 04 検証・改善／review | 実施した確認、得た反応、具体的な改善前後 |
| 05 成果と効果／outcome | 実測値や確認済みの変化、できるようになったこと・学び |
| 06 使用技術・ツール／tools | 名前・用途・採用理由、関連する制約 |

機能一覧の羅列より、利用者の課題→操作→解決のつながりを伝える。使ってほしい想定人数を実際の利用者数として書かない。未公開デモ・非公開GitHubでも、提供されていないURLは補わない。目次はcontents、章が増減したら目次も更新する。
