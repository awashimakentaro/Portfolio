# 表紙を仕上げる

表紙段階の成果物は、作品名・カテゴリの装丁・画像・リンクが揃い、実際の大きさで見て操作できる表紙。設定ファイルの作成だけで完成としない。

## 1. 不足する情報だけ確認する

既存book.ts・cover.ts・intake.md・images/・公開設定を先に読む。

- 表示する正式名称と表記。英語表記が既に確定していればそのまま使う。PortfolioはAwashima Portfolio。
- Apps / Agents / Design / Internshipのどれか。
- 表紙に使う画面・サムネイル。複数候補なら作品が伝わる候補を1つ示して理由を添える。新しい画像を実績として捏造しない。
- DemoとGitHubの実URL、および掲載の扱い。未提供なら省略し、「非公開」とは勝手に決めない。

本人に一括の必須フォームを埋めさせず、今の判断に必要な1問だけを尋ねる。掲載可能な画像がない場合は共通装丁と名称・既存リンクだけで先に表紙を作る。

## 2. 共通の装丁に配置する

| 保存先 | 内容 |
|---|---|
| book.ts | 作品名・カテゴリ・Demo/GitHub。cover.tsへ同じ文字を二重登録しない |
| cover.ts | 既存共通装丁・任意の表紙画像とalt・draft/ready |
| images/ | 表紙に使う実物素材 |
| intake.md | 選定した画像・トリミング判断・不足・確認結果 |

共通装丁はApp.png／Agent-v2.png／design.png／internship.png。Agentsは画像枠のないAgent-v2.pngを使い、サムネイルや画像枠を追加しない。作品名は表紙の上側に、Engineering Learningは1行で収める。提供されているDemo／GitHubは従来の下側に置く。旧Agent.pngを現行の表紙へ戻さない。Apps・Design・Internshipでは指定画像を作り直さず、上部白枠いっぱいに中央トリミングで写真を置く。`src/lib/book-layout.mjs`の固定枠を使う。小さな独自の画像枠へ戻さない。重要なUI・キャラクター・文字が切れる場合は別画像や提供画像の選定を見直す。

会社ロゴなど、全体を見せる必要がある画像は`cover.ts`の`image.fit: 'contain'`を使い、縦横比を保って枠内へ配置する。`image.background`は元画像に合う6桁HEX色。原本PNGは加工せず保存し、Studioと本体の共通配置で既定で8%の安全余白を確保する。横長の画面画像を横幅いっぱいに見せたい場合は、`image.fit: 'contain'`と`image.inset: 0`を使う。上下の余白は許容し、縦横比を変形しない。insetは0〜0.2の割合で、Studioと本体で共用する。写真の既定値は従来の`cover`。本体用の`thumbnailFit`と`thumbnailBackground`はsnapshotとbook:syncで生成し、手編集しない。

英語作品名を大きく置き、長い名称は折り返しと余白で収める。読めなくなるほど縮めない。Portfolioで確定したタイトル・リンクの上寄せは共通配置を維持する。

リンクは「Demo」「GitHub」とアイコンを組み合わせた、背景と細い枠のある丸いボタン。小さなテキストリンクだけにしない。PCの通常表示で読める文字サイズと押せる高さを確保する。ボタンなし／1つ／2つの場合を扱い、ないリンクをダミーで追加しない。

Apps・Agents・Designでは掲載できる実URLが存在するボタンは必須。Diet Appの中央表紙を基準とし、本文へのリンク掲載だけでは完了にしない。制作book.ts.linksと公開設定、中央・左右の表紙のボタン表示を照合する。ボタンは全位置で常時印刷し、操作とホバー演出は中央の閉じた本だけに限定する。左右のボタン位置を押しても外部リンクは開かず、中央へ選択する。選択変更によるボタンの追加・削除や表紙テクスチャ再生成をしない。全カテゴリの制作・在籍時期は`book.ts.details.period`を正本として、表紙右下へ小さく右揃えする。`2026.03–04`のように同じ年の範囲では終了側の年だけ省略し、同月は`2026.02`、継続中は`2026.06–現在`とする。年しか確認できない場合は`2026–現在`として精度を維持する。TERM等のラベル・枠・背景は付けない。「頃」・推定の制作月数は表示しない。会社名の下への大きな期間表示は使わない。元画像の固定座標COVER_DATEでStudioと本体を揃え、選択状態を理由に期間を消したり表紙を再生成したりしない。公開指定は全カテゴリのcoverPeriodを使う。

3Dの描画矩形とクリック矩形はcoverLinkRectsを共用する。見た目だけ大きくして判定範囲を小さいままにしない。画像・タイトル・ボタンを重ねず、装丁の外へ出さない。

## 3. 実際の見え方と操作を確認する

Studioで表紙を表示し、画像の収まり・作品名の読みやすさ・アイコンとラベル・リンク先・キーボードフォーカスを確認する。小画面では装丁の下にはみ出さず、2つのボタンが重ならないことを見る。

本番表示の更新も依頼されている場合は、本人の指定に沿って明示的な反映手順を実行し、Historyの中央本で確認する。

- DemoとGitHubを押すと、それぞれ指定先の新しいタブが開く。
- リンクを押しても本が開かない。
- ボタンの文字だけでなく、枠の内側・端も押せる。ボタン間の隙間でリンクを開かない。
- 表紙のリンク以外を押すと従来どおり本が開く。

外部サイトをテスト用応答に置換した場合は、URLとタブ起動の確認であることを記録し、外部サイト自体の稼働確認と混同しない。

## 4. 表紙段階の記録

intake.mdに「採用した名称・装丁・画像・URL」「見え方の確認結果」「操作の確認結果」「残る素材・本人の修正」を保存する。表紙のプレビューを示してからフィードバックを反映する。表紙だけの依頼はここで完了とし、本文を変更しない。全体制作なら確認済みの内容を基に本文へ進む。画面を確認できなかった場合は未確認と明記する。

## ホバーの反応

Demo／GitHubの各ボタンにカーソルを置くと、カテゴリボタンと同系統の淡い金色の光が約0.65秒で一度横切り、対象の枠を明るくする。外れると収める。Studioではキーボードフォーカスにも反応させる。動きを減らす設定では光の移動を止め、静的な強調だけにする。本体はクリック領域と同じ矩形でGPUの重ね描きを使い、ホバーのたびに表紙テクスチャを再生成しない。
