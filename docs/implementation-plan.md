# ポートフォリオ 実装計画

- バージョン: 1.0
- 状態表記は **確定**・**提案**・**未確認**。
- 目標：PC優先の新規ポートフォリオを実装し、Vercelへ公開する。PC全体画像、2026-11-04付ビジュアル仕様、3D Book引き継ぎ書は確認済み。Figma原本と細部の数値は未確認のため、そこは確定扱いにしない。

## フェーズ0 — 元資料の回収と棚卸し

1. FigmaデザインファイルのURLと対象フレーム/node-idを受け取り、Designerが参照できることを確認する。PC全体画像・最新仕様・Book引き継ぎ書は特定済み。
2. 会話にあるヒアリング01〜07の決定事項を資料に照合する。未提供・取得不能な記録は未確認のまま残す。
3. キャラクター・本素材の実ファイルを確認し、場所、枚数、命名、寸法、形式、総バイト数、利用条件を記録する。
4. 最終メール/GitHubリンクと、承認済みの作品説明、サムネイル、Demo/リポジトリURLを記録する。
5. 確定したビジュアル判断をデザイントークンにし、本書を更新する。

**終了条件：** 未解決入力が提供済み、または明示的に保留として合意されている。素材棚卸しが実ファイルに基づいている。

## フェーズ1 — アプリケーション基盤

1. Next.js App Router＋TypeScriptで新規アプリを作る。（App Routerは提案。依存バージョンは実装時に選定・固定）
2. Figma原本を確認し、承認されたデザインに合わせてスタイル、フォント、共通ページ枠を構成する。
3. Profile、About、Works、Contactの意味構造を作り、アニメーションやWebGLなしでも動くレスポンシブな骨組みを用意する。
4. Vercelビルド・デプロイ設定と実行環境の境界を整える。

**終了条件：** クリーンビルドが通り、アニメーション・WebGLなしでもページ構造が利用できる。デザイントークンが承認済みデザインに基づいている。

## フェーズ2 — コンテンツモデルとWorksの土台

1. 作品/カテゴリの型付きメタデータを定義し、ID重複、カテゴリ、Markdownパス、任意URLを検証する。
2. 確定済みの4カテゴリと7作品を登録する。未確認の文言、素材、URLは作らず、空欄のままにする。
3. Markdownファイルと、許可リストに基づく型付きページモデル変換処理を用意する。
4. アクセシブルなHTMLでカテゴリナビゲーション、作品一覧、本の選択を実装する。

**終了条件：** 7作品が正しいカテゴリに一度ずつ表示され、任意コンテンツ欠落や不正データでページ全体が停止しない。

## フェーズ3 — キャラクター連番の単独試作

1. HTMLの`<img>`、URL解決、先読み状態、エラー状態、フォールバック、重複排除した画像読み込みを持つ`FrameSequence`を実装する。
2. 実際の素材棚卸しに基づくマニフェストを作る。推測した枚数やファイル名をハードコードしない。
3. PCのポインター位置から目標フレームを選び、逆方向マッピングとrAF補間を実装する。
4. モバイル静止画表示と動きの低減設定を実装する。
5. 実測した読み込み状況に応じて先読み範囲とキャッシュ方針を決める。

**終了条件：** ポインターで滑らかにポーズが変わる。通常読み込みで壊れた画像が点滅せず、モバイルは静止し、失敗時にフォールバックが見える。

## フェーズ4 — HeroからAboutへの可逆遷移

1. 遷移区間の正規化進捗関数と名前付き調整定数を定義する。
2. 承認デザインに基づいて進捗から連番フレーム、位置、サイズを計算する。
3. 同じ進捗を操作主体の切替に使用し、引き継ぎに隙間や重複が出ないようにする。
4. 高頻度の読み書きを単一のrAFループにまとめ、複数のアニメーション主体を避ける。
5. 下スクロールと上スクロール、急な方向転換、画像未読み込み時を確認する。

**終了条件：** 各中間状態がスクロール進捗から決定的に再現され、上スクロールで正確に巻き戻り、合意した境界でHero操作が戻る。

## フェーズ5 — 3D Bookの縦切り実装

1. 詳細設計書から形状、操作、ページ本文、状態遷移の要件を抽出する。
2. React Springと、引き継ぎ書に指定されたR3F/Three.jsを使い、本1冊の独立した実装を行う。CanvasTextureなど試作固有の選択は個別に仕様照合する。
3. 明示的な状態・イベントと、競合操作の制御を実装する。
4. Markdown作品1件をページモデルにし、設計仕様に基づきページ/CanvasTextureへ描画する。
5. ロード/エラー/WebGLフォールバック、フォーカス可能な操作、動きの低減設定を加える。
6. 開く、閉じる、次へ、前へ、端のページ、作品変更、アニメーション完了、エラー回復を確認する。

**終了条件：** 単一Bookが詳細設計書の完了条件を満たす。設計書を回収・照合するまでは3D Book全体を完成扱いにしない。

## フェーズ6 — Worksとコンテンツの完成

1. 承認後に7作品すべてのMarkdown本文を記入する。
2. 承認されたサムネイル、表紙、外部リンク、表示順を追加する。
3. PCとモバイルの対象サイズでカテゴリ切替と本の動作を確認する。
4. 実測した素材、モデル、テクスチャ容量に基づき遅延読み込みとメモリ使用量を調整する。

**終了条件：** 7作品が正しく表示され、任意項目がないものはそのUIを隠し、カテゴリ選択と本を操作できる。

## フェーズ7 — 統合、アクセシビリティ、性能

1. キャラクター、背景、本を統合する。アニメーション値の可変所有者を共有しない。
2. キーボードのみでの操作、フォーカス、意味構造、代替テキスト、動きの低減、狭い画面を確認する。
3. WebGL非対応、画像の遅延/失敗、スクロール反転、タブ非表示、ブラウザーリサイズを確認する。
4. 実ファイルの容量と性能測定値を記録し、実測に基づいて形式や先読みを最適化する。
5. 承認済みのプロフィール情報・文面でSEOタイトル、説明、SNSメタデータを設定する。

**終了条件：** `requirements.md`の完了条件を対象ブラウザー・端末で満たし、素材容量や性能の主張が推定値に基づいていない。

## フェーズ8 — Vercel公開

1. リポジトリをVercelへ接続し、コミット済みロックファイルに基づくビルド設定を確認する。
2. プレビュー環境でパス、大文字小文字を含む素材URL、実行時エラー、モバイル表示、外部リンクを確認する。
3. プレビューを確認後、本番へデプロイし、ロールバック/再デプロイ手順を記録する。

**終了条件：** 本番URLですべてのセクションと素材が表示され、Vercelビルドを再現できる。

## 依存バージョン・素材容量の方針

- 互換性を確認して採用するまで依存バージョンを記載しない。実装時に解決した正確なバージョンをマニフェストとロックファイルに固定する。
- 素材容量は推定しない。配信先を決める前に、実ファイルの枚数、寸法、形式、バイト数を計測する。
- 試作リポジトリは挙動の参考資料として扱う。確認済みの参考値（遷移122フレーム、Hero基準42/85/127、補間係数0.12、閾値・区間）は、実素材とデザインで再確認する初期値である。
