# 分かったこと

## ワイヤーフレームとは

ワイヤーフレームは、色・写真・細かな装飾より前に、**画面の骨組みと利用者の動線**を確かめるための設計図。主に次を決める。

- この画面で利用者に達成してほしいこと
- そのために必要な情報の順序と優先度
- ボタンや入力欄など、操作できる場所
- 画面遷移、正常時・失敗時・空の状態などの分岐

完成度は低くてよい。紙のラフ、ホワイトボード、FigJam、Figma、スライドなど、目的に合う道具で作れる。

## Figmaは使うべきか

**必須ではないが、Web・アプリのポートフォリオならFigmaを最初の標準にするのがおすすめ。**

理由は、複数画面を並べる、コメントで相談する、画面をつないで操作を試す、コンポーネントを再利用する、という一連の流れを一つの場所で行えるため。Figma以外に、初期の発散には紙やFigJam、動く仮説の検証にはコード生成型AIも使える。

## 画面に落とし込む前に集める情報

画面から考え始めず、次の順で整理するとぶれにくい。

1. **目的**：誰の、どんな困りごとを、何ができる状態に変えるか。
2. **利用者と場面**：誰が、いつ・どこで・どんな端末から使うか。
3. **最短タスク**：利用者が開始から完了までに取る行動。例：商品を比較して購入する。
4. **必要な情報・機能**：各場面で見せる情報、入力、選択肢、ルール。
5. **優先順位と制約**：最重要の行動、締切、既存ブランド、技術・法務上の制約。
6. **例外状態**：未入力、エラー、読み込み中、結果なし、初回利用など。

情報を「画面一覧」に直行させず、まず利用者の行動を矢印でつないだ**ユーザーフロー**にする。ワイヤーフレームは、そのフローの各場面を一画面ずつ具体化したもの。

## 現在の主流：AIを“初案と試作の加速器”として使う

いまは、次のハイブリッド型が実用的。

```text
課題・利用者・タスクを言語化
          ↓
AIでフロー案／画面案を複数出す
          ↓
人が優先順位・文言・例外状態を選び直す
          ↓
Figmaで構造を整え、クリックできる試作にする
          ↓
利用者や関係者に試してもらい、直す
```

Figmaでは、Figma AIのFirst Draftで画面案を出す方法と、Figma Makeで文章・既存フレーム・PDFなどを文脈として渡し、動くプロトタイプまで作る方法がある。Makeは、プロンプトで作成してから画面上で編集し、再度AIに修正を頼める。つまり、AIで一枚絵を量産するより、**前提情報を渡して素早く仮説を作り、検証のために編集する**使い方が中心になっている。

ただし、AIは「何を優先するか」「その導線が利用者にとって自然か」「必要な状態が漏れていないか」を自動で保証しない。出力は完成品ではなく、検討用のたたき台として扱う。

## ポートフォリオでおすすめの最小手順

1. 1ページに「対象ユーザー・課題・達成させたい行動」を各1〜2文で書く。
2. 代表的な利用シーンを一つ選び、開始から完了までを5〜8個程度の行動に分ける。
3. 各行動に対応する画面を、灰色の箱とテキストだけで置く。
4. 各画面に「主目的」「主ボタン」「必要情報」「戻る先・次へ進む先」を注記する。
5. 画面をつなぎ、第三者に代表タスクをしてもらう。
6. 導線が固まってから、色・フォント・写真などのビジュアルデザインへ進む。

## AIに渡すとよい入力

AIの精度は、ツール名よりも前提情報で決まる。最低限、次を一緒に渡す。

- プロダクトの目的と対象利用者
- 代表タスクと完了条件
- 画面種別（Web/スマホ）と主要な画面数
- 必要な情報・機能、避けたいこと
- 既存のブランド、デザインシステム、参考画面
- エラー・空状態・確認画面など、考慮する状態

例：

> 忙しい個人事業主が、請求書を作成して送付するWebサービスの低忠実度ワイヤーフレームを作成。代表タスクは「取引先を選び、明細を入力し、内容を確認して送付」。ダッシュボード、請求書作成、確認、送付完了の4画面。最優先は迷わず送付完了まで進めること。読み込み中・入力エラー・明細なしの状態も含める。色・写真は不要で、情報の優先度が分かる構造にする。
