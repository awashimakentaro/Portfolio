# awashima-world ユーザーフロー・インタラクション設計

## 1. この設計の目的

「企画・要件定義（最終版）」と「機能・情報設計」をもとに、訪問者が目的を達成するまでの行動の順番を整理する。

この工程では、画面内の細かい配置ではなく、次のことを決める。

- どのページから始まるか
- ユーザーが何を確認するか
- 次にどこへ進めるか
- どこで判断・離脱・問い合わせが起きるか
- 主要導線と補助導線をどう分けるか

## 2. 前提

- 最優先ユーザーは、UI/UXデザイン会社の面接官・採用担当者
- 採用担当者は、短時間で職種・強み・代表作品・担当範囲・成果を確認したい
- 作品詳細は、課題・プロセス・成果・学びを同じ順序で確認できるようにする
- 本人の担当範囲は、Internships内の各インターン先詳細で確認できるようにする
- キャラクターや淡嶋AIは補助導線であり、主要情報へ進む導線を代替しない
- 回答4件（うち1件は仮想ペルソナによる合成回答）をもとにした仮説であり、公開後に検証する

## 3.1 インタラクション設計の範囲

この工程では、ページ遷移だけでなく、ユーザー操作に対するサイトの反応を設計する。完成した見た目やアニメーションの秒数を決める工程ではない。

### 対象とする反応

- クリック、ホバー、フォーカス、スクロールに対する状態変化
- キャラクターの登場、案内、表情や動作の切り替え方
- アニメーション開始・終了の条件
- 音声・効果音の再生条件と停止方法
- 読み込み中、エラー、3D非対応、音声OFF、アニメーション軽減時の代替状態

### 主な成果物

- ユーザーフロー図
- インタラクション仕様
- 必要に応じた状態遷移図
- 主要操作と演出の対応表

演出がなくても主要情報へ到達できるか、演出が操作や閲覧を遅らせないかをこの段階で確認する。具体的なビジュアルは06、操作可能な検証は07、技術選定と実装は08で扱う。

## 3. フロー全体

```text
入口
  ↓
ファーストビューで「何をしている人か」を理解
  ↓
代表作品、プロフィール、またはインターンシップを選択
  ├─ 代表作品 → メインページの作品一覧 → GitHubリポジトリ / デモ または作品詳細 → トップページ → フッターのメール
  ├─ プロフィール → About → Works / トップページ → フッターのメール
  ├─ インターンシップ → インターンシップ一覧 → インターン先詳細 → 関連作品 / About / トップページ
  ├─ Works内のawashima-world詳細 → 制作過程 → GitHubの制作メモ
  └─ キャラクター・淡嶋AI → 情報を知る → Works / About / Internships / フッターのメール
```

## 4. 主要フローA：採用担当者が代表作品を評価する

### 目的

短時間で、淡嶋の志望職種・強み・代表作品・成果を理解する。本人の担当範囲は、Internshipsから確認する。

### フロー

```text
トップページへ訪問
  ↓
ファーストビューを見る
  ↓
志望職種・強み・代表実績を確認
  ↓
「代表作品を見る」を選択
  ↓
作品一覧を見る
  ↓
作品名・何を作ったか・GitHubリポジトリURL・デモURLを確認
  ↓
気になる作品を選択
  ↓
作品詳細を見る
  ↓
課題・目標・プロセス・成果・学びを確認
  ↓
必要に応じてInternshipsで担当範囲を確認
  ├─ さらに確認したい → GitHubリポジトリ / デモ / 成果物
  ├─ 他作品も見る → 次の作品 / 作品一覧
  └─ 連絡したい → トップページ → フッターのメール
```

### 成功条件

- ファーストビューだけで、何を目指している人か説明できる
- 代表作品へ迷わず移動できる
- 作品詳細を見て、作品の課題・プロセス・成果・学びを説明できる
- Internshipsの各インターン先詳細で、本人の担当範囲を確認できる
- 詳細確認、外部リンク、連絡のいずれかへ進める

### 失敗・離脱の可能性

- ファーストビューで職種や強みが分からない
- アニメーションやキャラクターの演出が長く、作品へ進めない
- 作品一覧で違いが分からない
- 作品詳細に成果や学びがなく、評価を続けられない
- Internshipsの各インターン先に担当範囲がなく、役割を確認できない
- GitHubやデモへのリンクが見つからない

### 設計上の対応

- 作品への導線をファーストビューから直接表示する
- 作品カードには作品名、何を作ったか、GitHubリポジトリURL、デモURLを表示する
- 作品詳細の情報順を全作品で統一する
- 成果・学びは作品詳細ページで確認できるようにする
- グローバルナビゲーションのInternshipsから、各インターン先の担当範囲を確認できるようにする
- 作品一覧と作品詳細の両方に、GitHubリポジトリURLとデモURLを見つけやすく表示する
- 主要情報は演出の完了を待たずに確認できるようにする

## 5. フローB：作品を比較して評価する

### 目的

複数の作品を同じ基準で比較し、デザイン・技術・課題解決の強みを判断する。

### フロー

```text
作品一覧
  ↓
作品カードを確認
  ├─ 作品名
  ├─ 何を作ったか
  ├─ GitHubリポジトリURL
  └─ デモURL
  ↓
作品Aの詳細
  ↓
「他の作品を見る」
  ↓
作品一覧へ戻る
  ↓
作品B・作品Cを同じ観点で確認
  ↓
気になる作品のデモを確認
```

### 比較する項目

| 項目 | 作品一覧での表示 | 作品詳細での表示 |
| --- | --- | --- |
| 作品名 | 作品名 | 作品名 |
| 作品の内容 | 何を作ったか | 背景・課題・目標 |
| 自分の関わり | Internshipsへの導線で確認 | 該当インターン先の詳細で確認 |
| 成果・学び | 作品詳細で確認 | 成果・効果・根拠・学び |
| 技術 | 作品詳細で確認 | 使用技術・ツールの詳細 |
| 実物 | GitHubリポジトリURL・デモURL | GitHubリポジトリURL・デモURL・詳細リンク |

## 6. フローC：作品詳細を深く読む

### 目的

作品の見た目だけでなく、課題設定、意思決定、検証、成果から実務能力を判断する。

### フロー

```text
作品詳細へ移動
  ↓
作品名・一言概要を確認
  ↓
課題・背景・目標を確認
  ↓
想定ユーザーと課題への向き合い方を確認
  ↓
制作プロセス・判断理由を確認
  ↓
検証・改善内容を確認
  ↓
成果・効果を確認
  ↓
GitHubリポジトリ / デモ / 成果物を確認
  ├─ もっと読む → 制作メモ
  ├─ 他作品を見る → 次の作品
  └─ 連絡する → トップページ → フッターのメール
```

### 情報の段階表示

最初に、次の要約を見せる。

- 何を作ったか
- どの課題を扱ったか
- 成果・学び
- 詳細・GitHub・デモへのリンク

これらは作品詳細ページで表示する。その後、詳しく知りたいユーザー向けに、背景、判断理由、検証、改善、今後の課題を表示する。
本人の担当範囲は、Internships内にある該当インターン先の詳細で確認する。

## 7. フローD：awashima-worldの制作過程を確認する

### 目的

ポートフォリオ自体を、企画・設計・実装・改善まで実践した作品として理解する。

### フロー

```text
トップページまたは作品一覧
  ↓
awashima-world詳細
  ↓
制作過程の概要を見る
  ↓
企画
  ↓
要件定義
  ↓
デザイン
  ↓
実装
  ↓
公開・改善
  ↓
改善
  ↓
詳細な制作メモ（GitHub）へ移動
```

### 各工程で確認できること

| 工程 | サイト内で伝えること | 詳細への導線 |
| --- | --- | --- |
| 企画 | 制作目的、対象ユーザー、解決したい課題 | 企画メモ |
| 要件定義 | 目的、必要機能、制作範囲、優先順位 | 要件定義メモ |
| デザイン | ワイヤーフレーム、UI、キャラクター、演出 | デザイン資料 |
| 実装 | 完成画面、技術、動作 | GitHub・デモ |
| 公開・改善 | 改善内容、改善前後 | 調査・改善メモ |

## 8. フローE：プロフィール・人柄を確認する

### 目的

経歴、志望職種、人柄、制作姿勢を知り、作品を見るときの評価軸を持つ。

### フロー

```text
トップページ
  ↓
About / Profile
  ↓
志望職種・経歴・得意領域を確認
  ↓
制作姿勢・人柄を確認
  ├─ インターンシップを見る → Internships
  ├─ 作品を見る → Works
  ├─ 制作過程を見る → Works / awashima-world詳細内のProcess
  └─ 連絡する → フッターのメール
```

### 注意点

プロフィールは重要だが、調査では代表作品や成果も先に確認される傾向があった。そのため、Aboutへの導線は用意しつつ、トップページで作品への導線を埋もれさせない。

## 9. フローF：インターン経歴と担当範囲を確認する

### 目的

インターン先ごとに、在籍中に何を担当し、どのような業務や制作を行ったのかを確認する。

### フロー

```text
グローバルナビゲーションのInternships
  ↓
トップページ内のインターンシップ一覧を確認
  ↓
インターン先を選択
  ↓
インターン先の詳細ページを見る
  ↓
在籍期間・担当範囲・実際に行ったこと・関連する制作内容を確認
  ├─ 関連作品を見る → 作品詳細
  ├─ 他のインターン先を見る → インターンシップ一覧
  ├─ Aboutへ戻る → About / Profile
  └─ ポートフォリオへ戻る → トップページまたは直前のページ
```

### 設計上の対応

- グローバルナビゲーションからインターンシップ一覧へ直接移動できるようにする
- インターン先は、作品と同じように一覧から詳細ページへ移動できるようにする
- 各インターン先の詳細ページに、在籍期間、担当範囲、実際に行ったこと、関連する制作内容を記載する
- 詳細ページからインターンシップ一覧、About、ポートフォリオへ戻れるようにする

## 10. フローG：淡嶋AI・キャラクターから回遊する

### 目的

キャラクターを通して、プロフィール、作品、考え方を楽しく知る。

### フロー

```text
キャラクターまたは淡嶋AIが登場
  ↓
訪問者が質問または案内を選択
  ├─ プロフィール → About
  ├─ インターンシップ → Internships
  ├─ 制作物 → Works
  ├─ 考え方 → About / awashima-world詳細内のProcess
  ├─ 詳細を見たい → 該当作品詳細
  └─ 連絡したい → トップページ → フッターのメール
```

### 必須条件

- AIを使わなくても主要情報へ到達できる
- 職種、担当範囲、成果などの重要情報をAI回答だけに任せない
- 回答から関連ページや作品へ直接移動できる
- 回答できない場合も、ユーザーを行き止まりにしない
- AIや演出の読み込みが、作品確認を遅らせない

## 11. 入口別の導線

| 入口 | 主なユーザー | 最初に確認する情報 | 主な次の行動 |
| --- | --- | --- | --- |
| トップページ | 採用担当者・協業者 | 職種・強み・代表作品 | Works、About、Internships、フッターのメール・個人GitHub |
| 作品一覧 | 採用担当者 | 作品名・何を作ったか・GitHubリポジトリURL・デモURL | 作品詳細、GitHub、デモ |
| 作品詳細 | 採用担当者・技術担当者 | 課題・プロセス・成果・学び | GitHubリポジトリ、デモ、次の作品、トップページ |
| About | 採用担当者・協業者 | 経歴・人柄・得意領域 | Internships、Works、トップページ |
| Internships | 採用担当者・協業者 | インターン先名・在籍期間・担当の要約 | インターン先詳細、About、Works、トップページ |
| インターン先詳細 | 採用担当者・協業者 | 在籍期間・担当範囲・実際に行ったこと | 関連作品、Internships、About、ポートフォリオ |
| awashima-world詳細 | 制作過程を見たい人 | 企画から改善までの流れ | 詳細なProcess、GitHubの制作メモ |

## 12. 行き止まりを作らないためのルール

- トップページへ戻る導線から、下部のフッターにあるメールアドレスと個人GitHubへ進める
- 作品詳細には、作品一覧へ戻る導線と次の作品への導線を置く
- 外部リンクを開いたあと、ポートフォリオへ戻れる情報を用意する
- AIが回答できない場合は、関連するAbout、Works、Internships、フッターのメールへの選択肢を示す
- GitHubやデモなどの外部リンクは新しいタブで開く
- 外部リンクの利用不可やリンク切れは、公開前の確認で検出する
- アニメーションを無効化・短縮しても、導線が失われないようにする

## 13. ユーザーフローからワイヤーフレームへ渡す情報

| 画面 | 必須の情報・要素 | 必須の導線 |
| --- | --- | --- |
| トップ | 職種、強み、代表作品、中心メッセージ、インターンシップ一覧、フッターのメール・個人GitHub | Works、About、Internships |
| 作品一覧 | 作品名、何を作ったか、GitHubリポジトリURL、デモURL | 作品詳細、GitHub、デモ |
| 作品詳細 | 課題、目標、プロセス、成果・学び、技術、GitHubリポジトリURL、デモURL | GitHubリポジトリ、デモ、次の作品、Internships |
| About | 経歴、得意領域、人柄 | Internships、Works、awashima-world詳細、フッターのメール |
| Internships | インターン先名、在籍期間、職種または担当の要約 | インターン先詳細、About、Works、トップページ |
| インターン先詳細 | 在籍期間、担当範囲、実際に行ったこと、関連する制作内容 | 関連作品、Internships、About、ポートフォリオ |
| awashima-world詳細内のProcess | 企画、要件定義、デザイン、実装、改善 | 詳細メモ、作品一覧 |
| フッター | メールアドレス、個人GitHubホームURL | メール、個人GitHub |

## 14. 完了基準

- 最優先ユーザーの主要フローが図で説明できる
- 各フローに目的、開始地点、行動、分岐、終了条件がある
- ファーストビューから代表作品へ進める
- 作品一覧から詳細、GitHub、デモへ進める
- 作品詳細からGitHubリポジトリ、デモ、次の作品へ進める
- グローバルナビゲーションからInternshipsへ進み、各インターン先詳細で担当範囲を確認できる
- インターン先詳細からInternships、Aboutまたはポートフォリオへ戻れる
- About、Internships、インターン先詳細、awashima-world詳細内のProcess、淡嶋AIが主要導線を邪魔しない
- 行き止まりになるページや分岐が把握できている
- ワイヤーフレームに必要な情報と導線を画面ごとに渡せる

## 15. 未決定・要検証

- ファーストビューから作品一覧へ進む操作数
- 作品一覧で表示する作品数と情報量
- 作品詳細の長さと、要約・詳細の分け方
- Aboutを独立ページにするか、トップページ内のセクションにするか
- 淡嶋AIを初期公開に含めるかどうか
- 実際の訪問者が、目的の情報へ何秒・何操作で到達できるか

これらは次のワイヤーフレームとプロトタイプで確認する。
