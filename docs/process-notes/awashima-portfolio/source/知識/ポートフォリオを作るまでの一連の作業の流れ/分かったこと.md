> このメモは、参照会話で整理した「ポートフォリオを作るまでの一連の作業の流れ」を、内容を省略せずMarkdownとして記録したもの。

## 1. 概要・目的

UI/UXデザイナーとしての制作プロセスを身につけるために、Webアプリの企画からデザイン、実装、評価、改善までを一通り経験する。

最終的な目標は、完成したWebアプリだけでなく、**どのような課題に対して、何を考え、どのように設計・検証・改善したのか**をポートフォリオで説明できる状態にすること。

## 2. 全体の制作フロー

1. **企画・要件定義** — 何を、誰のために作るのか。3D・演出の目的と必要条件も定める
2. **ユーザー調査・課題整理** — どのような課題が存在するのか
3. **機能・情報設計** — 必要な機能や情報、演出なしでも成立する構造を整理する
4. **ユーザーフロー・インタラクション設計** — ページ遷移と、操作に対する反応・状態変化を設計する
5. **ワイヤーフレーム制作** — 情報や要素をどこに配置するのかを決める
6. **UI・ビジュアルデザイン制作** — 配色、文字、余白、コンポーネント、3D素材や演出の見た目を設計する
7. **プロトタイプ制作・検証** — 操作、導線、演出、代替状態が自然に機能するか確認する
8. **Webアプリ・3D演出実装** — Webアプリ、3D、モーション、音声などを必要な範囲で実装する
9. **公開・ユーザーテスト** — 実際に利用してもらい、演出を含む体験を確認する
10. **分析・改善** — 調査結果や利用データを基に改善する
11. **ケーススタディ作成** — 一連の制作過程と判断理由をポートフォリオとしてまとめる

※ 実際の制作では各工程を何度も行き来する。必ずしも一方向ではない。

---

## 3. 各工程の詳細

### STEP 1：企画・要件定義

**目的：何のために、誰に向けて、何を作るのかを明確にする。**

使用ツール：Notion / Obsidian

整理する項目：

- プロダクト名
- 制作の背景
- ターゲットユーザー
- 解決したい問題
- プロダクトが提供する価値
- 必要な機能
- 制作範囲（MVP）
- 成功指標

**成果物：企画書・要件定義メモ**

### STEP 2：ユーザー調査・課題整理

**目的：制作者の思い込みではなく、ユーザーの実際の問題を把握する。**

主な方法：

- ユーザーインタビュー
- アンケート
- 既存サービス・競合調査
- ユーザーの利用状況の観察

収集した情報を整理し、共通する課題やニーズを抽出する。

必要に応じてペルソナやユーザージャーニーマップを作成する。ただし、実際の調査で確認できていない情報は仮説として扱う。

**成果物：調査結果・課題一覧・ユーザーニーズ**

### STEP 3：機能・情報設計

**目的：課題解決に必要な機能と、ユーザーに見せる情報を整理する。**

実施内容：

- 必要な機能を洗い出す
- 機能に優先順位をつける
- MVPに含める機能を決める
- 情報の分類と階層を考える
- 画面一覧やサイトマップを作成する

**成果物：機能一覧・情報構造・画面一覧**

### STEP 4：ユーザーフロー・インタラクション設計

**目的：ユーザーが目的を達成するまでの操作の流れと、操作に対するサイトの反応を明確にする。**

例：

ホーム画面 → 課題登録 → 入力内容確認 → 保存 → 課題一覧に反映

考えること：

- ユーザーはどこから操作を開始するのか
- 目的達成までに何が必要なのか
- 無駄な操作や迷いやすい箇所はないか
- エラー時にどう対応できるか

**成果物：ユーザーフロー図・インタラクション仕様・必要に応じた状態遷移図**

### STEP 5：ワイヤーフレーム制作

**目的：画面内の情報配置やレイアウトを決定する。**

使用ツール：Figma

主な作業：

- 各画面に必要な要素を配置
- 情報の優先順位を決定
- ナビゲーションを設計
- ボタンやフォームの配置
- 画面間の整合性を確認

この段階では配色や装飾よりも、情報構造と操作性を優先する。3Dや演出は仮の領域・状態で扱い、演出なしでも主要情報と操作が成立するようにする。

**成果物：低忠実度ワイヤーフレーム**

### STEP 6：UI・ビジュアルデザイン制作

**目的：ワイヤーフレームを基に、視覚的に分かりやすく一貫性のある画面を設計する。**

使用ツール：Figma

主な作業：

- 配色設計
- タイポグラフィ設計
- 余白・レイアウト設計
- ボタン・カードなどのコンポーネント作成
- 各コンポーネントの状態設計
- レスポンシブ対応
- アクセシビリティの確認
- 3Dキャラクター、背景、エフェクトのビジュアル案
- モーション・音声表現の参考資料

必要に応じて簡単なデザインシステムを作成する。3Dモデルや演出の完成形はこの段階で確定せず、仮素材を使って検討できるようにする。

**成果物：高忠実度UIデザイン・コンポーネント集**

### STEP 7：プロトタイプ制作・検証

**目的：実装前に操作の流れや使いやすさを確認する。**

使用ツール：Figma

主な作業：

- 画面間を接続する
- ボタン操作や画面遷移を再現する
- ユーザーに操作してもらう
- 迷いや誤操作が生じる箇所を確認する
- 必要に応じて設計を修正する
- クリック、ホバー、スクロール、フォーカス、音声、アニメーションの反応を試す
- 3D演出の小規模な技術検証を行う
- 演出を減らした場合や利用できない場合の代替体験を確認する

**成果物：操作可能なプロトタイプ・検証結果**

### STEP 8：Webアプリ・3D演出実装

**目的：デザインと検証結果を、必要な3D・モーション・サウンドを含む動作するWebアプリとして実現する。**

使用技術の例：Next.js / React / TypeScript / Three.js / React Three Fiber / GSAP / Blender / Spline。候補であり、内容・性能・学習コストを見て選定する。

主な作業：

- 開発環境の構築
- UIコンポーネントの実装
- レスポンシブ対応
- 必要な機能の実装
- エラー処理
- 動作確認
- デプロイ
- 3Dアセット、アニメーション、音声・効果音の統合
- 音声OFF、アニメーション軽減、3D非対応環境の代替対応

**成果物：公開可能なWebアプリ・3Dアセット・演出・実装コード・技術検証記録**

### STEP 9：公開・ユーザーテスト

**目的：実際のユーザーがどのように利用するかを調べる。**

使用ツールの例：

- Google Forms
- Google Analytics
- ユーザーインタビュー

確認する項目：

- ユーザーが目的を達成できたか
- どの操作で迷ったか
- 情報は見つけやすいか
- 改善を求められた箇所はどこか
- 実際の利用状況はどうか
- 演出が理解を助けたか、操作や閲覧を妨げたか

Google Analyticsなどの行動データだけでは使いにくさの理由までは分からないため、アンケートや観察と組み合わせる。

**成果物：ユーザーテスト結果・分析データ**

### STEP 10：分析・改善

**目的：調査や利用データから問題を発見し、改善する。**

基本サイクル：

1. 問題を発見する
2. 原因を分析する
3. 改善仮説を立てる
4. 改善案をデザインする
5. 実装・検証する
6. 改善前後を比較する

改善前後の画像や、変更の判断理由を記録する。

**成果物：改善案・改善履歴・検証結果**

### STEP 11：ケーススタディ作成

**目的：制作過程をUI/UXデザイナーとして説明できる形にまとめる。**

ケーススタディに含める内容：

- プロダクトの概要
- 制作背景と課題
- 自分の担当範囲
- ユーザー調査
- 課題の分析
- 要件と設計方針
- ワイヤーフレーム
- UIデザイン
- プロトタイプ
- テストと改善内容
- 最終成果物
- 学びと今後の課題
- 3D・モーション・音声・インタラクションを採用した理由と検証結果

重要なのは、完成画面を見せるだけでなく、**デザインの意思決定とその根拠を伝えること**。

| Notion / Obsidian | 企画・要件・調査・意思決定の記録 |

## 5. 制作時の重要な考え方

### デザインには理由を持たせる

「見た目が良いから」だけでなく、ユーザーの課題や行動に基づいて設計する。

### 最初から完成形を目指さない

小さく制作し、検証と改善を繰り返す。すべての機能を最初から実装する必要はない。

### 制作過程を記録する

各工程で、以下を記録する。

- 何を考えたか
- なぜその判断をしたか
- どのような案を比較したか
- どのような問題が見つかったか
- 何を改善したか
- 結果はどうだったか

### UIとUXを区別して考える

- **UI**：ユーザーが触れる画面や操作要素の設計
- **UX**：ユーザーが目的を達成するまでの体験全体の設計

優れた見た目だけでは、優れたUXとは限らない。

## 6. 最初の制作で意識すること

最初のプロジェクトでは、複雑なWebアプリを作るよりも、少数の主要機能に絞って、一連の工程を最後まで経験することを優先する。

**最終目標：課題発見 → 設計 → デザイン → 実装 → 検証 → 改善という流れを、自分の成果物を使って説明できるようになること。**
