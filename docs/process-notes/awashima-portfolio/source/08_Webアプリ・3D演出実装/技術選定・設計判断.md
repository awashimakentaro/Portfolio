# Web実装の技術選定・設計判断

## 背景とキャラクターを、一体の映像にする

最初はキャラクターだけを切り抜き、背景は別に作る構想だった。両者の動きを連動させる難しさに気づき、背景とキャラクターを一緒に動画で作り、連番フレームに分ける方法へ変更した。

位置や姿勢、カメラの動きを映像に含め、Web側では区間の再生とUIの表示を合わせる。今回選んだ方法であり、別実装が一般に不可能という意味ではない。

## 作品詳細を共通の本にまとめる

作品詳細・インターン詳細を別ページにする案は、背景演出の実装コストと体験の一貫性を考えて見直した。

本という共通の表示方式に、各作品・経験に合う内容を載せる。紹介する情報と管理方法を揃えつつ、カテゴリに応じて章の内容は変えられる構成にした。

本棚から選ぶ案も、操作の手数と認知負荷を考慮し、Historyの映像上で直接本を選べる一覧へ変更した。工数や認知負荷を数値で比較した結果ではなく、本人の設計判断である。

## ライブラリを調べ、紙の表現へつなげる

AIへ曖昧に任せるだけでなく、必要な表現を考え、使える技術を調べた。

- **React Three Fiber・Three.js**：本を3Dで描画する。
- **SkinnedMesh**：骨の回転を紙の幅へ分布させ、湾曲してめくれる形にする。
- **React Spring**：開閉やページめくりの進行を制御する。

完成済みの本表示ライブラリをそのまま置いただけの構成ではない。

## 背景の入力と、本の操作を競合させない

本を開く・読む・閉じる間は背景のシーン移動を禁止し、映像のループは続ける。ナビで別画面が指定された場合は、本を閉じてから移動する。

文字とナビはHTML UIとして背景・本の3D描画から分け、映像の到達タイミングに合わせて表示する。

## 制作原稿と公開データを分ける

作品ごとにTypeScriptの設定、Markdown本文、画像、リンクを管理する。制作中の原稿を保存しただけでは公開せず、確認した原稿を明示的に公開用スナップショットへ反映する。

本の中身を調整する作業と、完成済みの映像・3D機構の変更を分けて進める。第三者評価の結果は今後追加する。
