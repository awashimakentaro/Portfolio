# ポートフォリオWeb実装計画：キャラクターと本型作品カタログ

## 目的

ポートフォリオの導入でキャラクターを見せ、その後、スクロールに合わせて大きな本が現れる作品カタログへつなぐ。目次から作品を選ぶと、サムネイル・概要・GitHubやデモへのリンクを確認でき、詳細は本のページをめくるように読める体験を作る。

本棚・本・ページのリアルタイム3Dは使わず、HTML/CSS/JavaScriptでレイアウトとページめくりを表現する。キャラクターは確定済みフレーム画像を使い、カーソル追従とスクロール連動はWeb側で制御する。作品ごとの映像制作やフレーム分解を必須にせず、作品データを共通テンプレートへ登録して追加できる設計にする。

## 採用する方式（決定）

```text
キャラクターのフレーム画像でヒーローを表示
    ↓ スクロール
大きな本の表紙が後方から現れて開く（CSS演出）
    ↓
目次：APP / AGENT / DESIGN / INTERNSHIP と作品名
    ↓ 作品を選択
サムネイル・概要・GitHub / Demoリンクを共通レイアウトで表示
    ↓ 詳細を選択
本のページをめくるように詳細情報へ切り替える（CSS / JavaScript）
```

作品一覧・詳細は通常のWebコンテンツとして実装する。動画やフレーム画像はキャラクターなど、動きを見せる必要がある箇所に限定する。

## 体験の流れ

### Scene 1：ヒーロー / キャラクター

- 完成済みのキャラクターフレーム画像を表示する。
- カーソルの横位置に合わせ、フレームを切り替えて向きを変える。
- キャラクターが画面内で案内役として存在する。
- 文字や操作の読みやすさを優先する。

### Scene 2：本が現れる

- スクロールに合わせて、一冊の大きな本が画面後方から現れる。
- 表紙が開き、目次ページへ移る。
- 本の厚みや奥行きはCSSのレイヤー・影・変形で表現する。
- 3Dモデルや生成動画は使わない。

### Scene 3：目次・作品一覧

- 目次に `APP / AGENT / DESIGN / INTERNSHIP` の4カテゴリを表示する。
- 各カテゴリの中に作品タイトルを並べる。
- 作品タイトルを選ぶと、サムネイル・短い概要・GitHub・Demoリンクを表示する。
- 作品情報はデータとして管理し、共通カードへ流し込む。

### Scene 4：作品詳細

- 詳細を開く操作を、本のページをめくるようなCSSアニメーションで見せる。
- 詳細本文、担当範囲、使用技術、成果、外部リンクを読みやすく掲載する。
- ページめくり演出が無効・低速端末でも、通常の画面切り替えで内容を読める。

## 必須要件

- キャラクターの基準デザインは、白い太い毛束・大きな目・黒い脚を維持する。
- 最初の画面で、キャラクターの目がカーソルを自然に追う。
- スクロールに合わせて本の出現・表紙の開きを制御する。
- 目次は4カテゴリ（APP / AGENT / DESIGN / INTERNSHIP）で構成する。
- 作品を追加する際、原則として作品データ・サムネイル・リンクの登録で表示できる。
- 詳細ページはページめくり風に切り替わり、内容はHTMLテキストとして読める。
- スマホではカーソル追従を使わず、目線がゆっくり動く待機表現に置き換える。
- `prefers-reduced-motion` が有効な環境では、動画を自動再生せず、静止画を表示する。
- JavaScriptやアニメーションが利用できない場合でも、目次・作品・詳細・Contactを通常のHTMLとして利用できる。

## 今回は実装しないこと

- キャラクターを360度回す操作
- 本棚・本・ページのリアルタイム3Dモデル
- 作品ごとに本を取り出す個別動画を制作すること
- リアルタイム物理演算
- 一本の長尺AI動画だけで全場面を作ること
- キャラクターとの会話機能

## 必要な素材

| 素材 | 内容 | 用途 |
| --- | --- | --- |
| 完成基準画像 | キャラクターの正面・上半身を中心にした高品質な画像 | 全映像の見た目をそろえる基準 |
| キャラクターフレーム画像 | 生成済み動画から抽出した向き違いの画像 | Scene 1のカーソル追従 |
| 作品サムネイル | 各作品の代表画像 | 目次から作品を選んだ後のプレビュー |
| 作品データ | タイトル、カテゴリ、概要、技術、GitHub、Demo、詳細本文 | 共通テンプレートに表示 |

### キャラクターのフレーム素材ルール

- ヒーロー映像の白目は大きく、カメラ位置は固定する。
- 画角・背景・キャラクター位置がそろったフレームを使う。
- カーソル位置と表示フレームの対応を確認し、左右の向きが自然になるよう調整する。
- 画像に背景がある場合は、ページ背景との合成状態を確認する。

## Web側の構成

```text
キャラクターのフレーム画像（カーソル追従）
  +
HTML/CSSの本・目次・作品カード・詳細本文
  +
CSSの表紙オープン・ページめくり演出
  +
スクロール位置と選択状態を扱うJavaScript
```

### 実装上の役割分担

| 要素 | 担当 |
| --- | --- |
| キャラクターの見た目 | Nano Banana Proなどの画像生成 |
| キャラクターの向き | 抽出フレーム画像とJavaScript |
| 本の表紙・厚み・ページ | HTML / CSS |
| 目次・作品情報 | HTMLテンプレートとJavaScriptの作品データ |
| ページめくり | CSS / JavaScript |
| スクロールで本を出す演出 | CSS sticky / transform、必要に応じてGSAP |

## 段階的な実装手順

### 段階0：キャラクター基準画像を決める

1. Nano Banana Proなどでキャラクターの完成基準画像を生成する。
2. 可愛さ、目、毛束、脚、質感が納得できるまで静止画だけを調整する。
3. この画像を以後の動画生成で毎回参照する。

### 段階1：ヒーローを静止画で成立させる

1. 完成基準画像をWebページに配置する。
2. 黒目を別HTML要素として重ねる。
3. カーソル位置に合わせ、黒目を少しだけ動かす。
4. 文字とキャラクターが干渉しないレイアウトを決める。

### 段階2：キャラクターフレーム追従を整える

1. 生成動画から抽出したフレームを使う。
2. カーソル位置と向きが対応するよう、フレームの範囲・順序を調整する。
3. PCとタッチ端末の操作を分ける。
4. 読み込み中・失敗時の静止画を用意する。

### 段階3：本の表紙と目次を作る

1. HTML/CSSで表紙・背表紙・ページの見た目を作る。
2. スクロール位置に合わせて本を後方から出現させる。
3. 表紙が開き、4カテゴリの目次が見える演出を加える。
4. モバイルでも本と目次が読みやすい寸法にする。

### 段階4：作品データと一覧を作る

1. 作品データの形式を決める（カテゴリ、タイトル、サムネイル、概要、技術、リンク、詳細）。
2. APP / AGENT / DESIGN / INTERNSHIPの目次を実装する。
3. 作品選択でサムネイル・概要・GitHub・Demoを表示する。
4. 仮データを実際のポートフォリオ作品に置き換える。

### 段階5：ページめくり風の詳細表示を作る

1. 目次または作品カードから詳細を開く操作を作る。
2. CSSでページがめくれる短い演出を付ける。
3. 詳細本文、成果、担当範囲、リンクをHTMLで表示する。
4. 閉じる・前後ページへ移動する操作を実装する。

### 段階6：仕上げとアクセシビリティ

- `prefers-reduced-motion` では本の出現・ページめくりを短いフェードに置き換える。
- PC・スマートフォンで操作、文字、リンクを確認する。
- JavaScriptや画像の読み込み失敗時も、作品情報へ到達できるようにする。
- アニメーションを含む画像の容量と初回表示速度を確認する。

### 段階7：公開前の確認

- PC・スマホで見た目を確認する。
- フレーム画像・サムネイル容量と初回読み込み速度を確認する。
- Reduced Motion時に演出を抑えることを確認する。
- JavaScriptが失敗しても必要な作品情報・リンクへ到達できることを確認する。

## 現時点の判断

- 本棚と本の3D化は行わず、CSSで本の表紙・厚み・ページを表現する。
- キャラクターはフレーム画像をカーソル位置に対応させる現在の試作を土台にする。
- 目次・作品一覧・詳細本文は通常のWebコンテンツとし、作品追加はデータ登録で行えるようにする。
- 本を取り出す演出や作品ごとの動画制作は要件に含めない。
- 作品情報の読みやすさとリンクの使いやすさを、ページ演出より優先する。
