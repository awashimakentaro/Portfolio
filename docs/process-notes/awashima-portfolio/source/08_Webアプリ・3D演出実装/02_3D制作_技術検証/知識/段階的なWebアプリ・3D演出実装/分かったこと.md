# 分かったこと

## 基本方針

最初に、3Dなしでもポートフォリオとして成立する画面と導線を作る。その後、3Dを独立した小さな技術検証として試し、効果・実現性・表示速度を確認してから本体へ統合する。

## 段階ごとの目的

| 段階 | 先に確認すること | 成果物 |
| --- | --- | --- |
| 1. 構成整理 | Profile → About Me → 本棚 → Contactの順番が自然か | 画面構成、情報の優先順位 |
| 2. 静的画面 | 文章、見出し、リンク、ボタンだけで内容が伝わるか | HTML / CSSの画面 |
| 3. 基本操作 | 本の選択、表紙、詳細、戻る操作が成立するか | JavaScriptの状態切り替え |
| 4. 仮表現 | キャラクターの位置や役割が適切か | 仮画像またはプレースホルダー |
| 5. 3D検証 | 3D表示・読み込み・操作・性能に問題がないか | 独立した小さな検証 |
| 6. 統合判断 | 3Dを入れることで理解や印象が本当に良くなるか | 採用・縮小・代替の判断 |
| 7. 仕上げ | 演出が情報到達を邪魔しないか | モーション、軽量化、代替状態 |

## リソースの配分

- 前半は、画面構成・情報設計・通常操作に多く配分する
- 3Dモデルやライブラリの調査は、静的画面の成立後に限定して行う
- 3Dは最初から本体へ組み込まず、最小の検証画面で実現性を確認する
- 3Dが使えない場合でも、文章・ボタン・リンクで主要導線を利用できるようにする
- 3Dの採用は「作れるか」だけでなく、「体験が良くなるか」「重くならないか」で判断する

## このポートフォリオへの適用

- 本棚の分類、本の選択、表紙、詳細、Contactを先に成立させる
- キャラクターは最初は案内役の仮表現にする
- 3Dキャラクター、スクロール移動、ページめくりは後段へ送る
- AIチャットや会話機能は実装対象にしない
