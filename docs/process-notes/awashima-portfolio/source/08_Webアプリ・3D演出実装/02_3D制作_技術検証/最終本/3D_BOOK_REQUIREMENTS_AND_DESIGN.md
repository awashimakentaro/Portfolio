# 3D Book Portfolio — 要件定義・技術選定・基本設計書

作成日：2026年11月5日 / 文書バージョン：1.0

## 1. この文書の位置づけ

作品を一冊ずつの3Dブックとして見せる、ポートフォリオの作品閲覧機能を定義する。実装者が、何を作るか・何を使うか・どのように分割するか・何を確認すれば完成かを判断できる文書とする。

ユーザーは既存アプリが起動できていると説明している。ただし、この作業環境では既存ソースを確認できていない。以下は既存の挙動を維持するための設計であり、現在の実装内容を保証するものではない。ソース入手後に実際の構成へ対応づけ、必要な箇所のみを変更する。

本文では「必須要件」と「推奨設計」「調整用の初期値」「未確定事項」を区別する。既存の引き継ぎ仕様を参照しつつ、その後に追加された大きな表示・黒い表紙・黒い内部ページの要件を反映する。

## 2. 目的と優先順位

作品の概要を表紙で把握し、Demo・GitHubへ移動し、興味を持った作品の詳細を本の中で読めるようにする。

優先順位は次の順とする。

1. 選択した本が、画面内で十分に大きく、美しく見える。
2. 黒いハードカバーと黒い紙に、厚み・質感・自然な陰影がある。
3. 選択・リンク・開閉・ページめくりが競合せず操作できる。
4. データ追加で作品を増やせる。
5. PC・モバイルで表示と操作を維持できる。

## 3. 対象範囲

対象は作品カルーセル、3Dブック、表紙、本文ページ、リンク、開閉・ページめくり、レスポンシブ表示とする。サイト全体のProfile・Contact、キャラクターのスプライトアニメーション、全体スクロール演出は別機能として扱う。

初期段階ではデータベース・管理画面・ログインを導入しない。本文の文字選択・コピー、物理エンジン、外部のページフリップライブラリも必須ではない。

## 4. 利用者の操作と必須要件

| ID | 場面 | 必須となる挙動 |
| --- | --- | --- |
| F01 | 初期表示 | 本を斜めに並べ、中央を主役とするカルーセルを表示する |
| F02 | 一覧操作 | 横ドラッグ・スワイプで中央の本を切り替える |
| F03 | 本の選択 | クリックした本が正面へ回転しながら拡大する |
| F04 | 正面表示 | 本は閉じたまま停止し、自動で開かない |
| F05 | 表紙リンク | 設定されたDemo・GitHubを操作できる。未設定のリンクは表示しない |
| F06 | 開く | Open book、またはリンク以外の表紙の余白をクリックすると開く |
| F07 | 読む | 黒い本文ページを表示し、ページ端のクリック・ドラッグでめくれる |
| F08 | 終了 | 本以外の背景をクリックすると閉じ、斜めのカルーセルへ戻る |
| F09 | 排他制御 | 移動・開閉・ページめくり中の入力競合を防止する |
| F10 | 作品追加 | データを追加することで共通の本として表示できる |
| F11 | 画面変更 | PC・モバイル・リサイズ時に本を画面内へ収める |

左右の本は中央より小さく斜めに配置し、重なりすぎを避ける。端の本も識別できる領域を残す。小画面では隣の本の一部が見える構成を許容し、中央の本の欠けを防ぐ。

## 5. ビジュアル要件

### 5.1 参考画像の使い方

ユーザー提供の2枚を基準とする。ファイル名だけで判別せず、空の表紙テンプレートと、サムネイル・文字・リンク入りの完成例を実画像で識別する。

特徴は、黒い革・布張りに近い細かな凹凸、擦れた縁、厚い背表紙、細い装飾線、白系のセリフ体、控えめなシアンの縁取りである。床・背景・側面を含む参考画像全体を、そのまま表紙の平面へ貼らない。素材・装飾・3D形状・動的コンテンツへ分けて再構成する。

### 5.2 表紙の共通レイアウト

| 上からの順序 | 内容 | 配置方針 |
| --- | --- | --- |
| 1 | プロジェクトサムネイル | 上部に大きく配置。枠は細く、画像の比率は維持する |
| 2 | タイトル | 視線の主役となる大きさ。長文は改行・縮小する |
| 3 | 短い説明 | タイトルより小さく、十分な行間を設ける |
| 4 | Demo・GitHub | 下部に横並び。片方だけなら中央寄せする |
| 5 | Open book | 最下部に独立したクリック領域を設ける |

レイアウト座標は表紙幅・高さに対する比率で管理する。タイトルは原則2行までを初期案とし、最小フォントサイズでも収まらない場合の省略と表示用短縮タイトルを設計する。本文・リンクと重なることを許容しない。

### 5.3 本の形状と素材

表紙・裏表紙・背表紙・紙束を別部品で構成する。表紙は薄い平面ではなく厚みと丸みを持たせ、背表紙付近には溝や段差を作る。革の色は完全な黒一色を避け、照明で凹凸を読めるようにする。

推奨素材はMeshStandardMaterial。表紙のbase color、roughness、normalまたはbumpを分ける。革・布部分のmetalnessは低くし、金属的な装飾があればその部分だけ別設定にする。色テクスチャはsRGB、roughness・normal等は非カラーデータとして設定する。

調整用の初期値：表紙roughness 0.75〜0.95、metalness 0〜0.05。これは見た目の完成値ではなく、実際の照明と合わせて調整する。シアンは縁の反射やボタンの細線に限定し、表紙全体を発光させない。

### 5.4 黒い本文ページ

紙の背景は #171719 を基準、文字は #E8E8E8、見出しはより明るく、本文は淡いグレーとする。本文の文字色は紙とのコントラストを実画面で確認する。

紙面に微細な粒状感、中央の綴じ目に曲線と影、外周に紙束の重なりを設ける。ページの裏面・断面・めくり途中も黒系で統一する。透過を使って裏面を見せない。

## 6. 技術選定

以下は採用方針であり、実際のバージョンは既存package.json・lockfileを調査して確定する。

| 技術・ライブラリ | 用途 | 方針 |
| --- | --- | --- |
| Next.js / React / TypeScript | ページとUI、型定義 | 既存の構成を維持する |
| three | 形状、素材、カメラ、骨格、テクスチャ | 3Dの基盤として使う |
| @react-three/fiber | Reactからの3Dシーン構築、描画更新、ポインターイベント | 本の表示を管理する |
| @react-three/drei | 補助形状・ライト等 | 必要な機能だけ使う |
| @react-spring/three | 位置・回転・開閉の補間 | 既存のアニメーション基盤を優先し、未導入なら第一候補とする |
| Canvas API / CanvasTexture | 動的な表紙文字・画像・本文 | プロジェクトデータから生成する |
| CSS / Tailwind CSS | ナビ・操作案内・代替表示 | 既存の方式を維持する |
| React useReducer / Context | 閲覧状態の管理 | この機能単体の初期案。既存ストアがあれば統合する |
| Playwright | 主要操作と画面サイズの検証 | 実装段階の開発依存として採用を検討する |

R3F公式の対応関係は、React 18にFiber 8、React 19にFiber 9である。既存のReactに合わせて選び、主要バージョンを独立に上げない。最新版への一括更新は本作業の前提にしない。

GSAPがサイト全体のスクロール制御に既に使われていても、本の同じposition・rotationをReact Springと同時に更新しない。部品ごとに値の更新責任を一つにする。ページ骨格のフレーム更新はuseFrameに集約し、React stateを毎フレーム更新しない。

## 8. データ設計

```ts
type BookType = 'type-1' | 'type-2' | 'type-3' | 'type-4';

type BookPage = {
  id: string;
  heading: string;
  body: string;
};

type BookProject = {
  id: string;
  bookType: BookType;
  title: string;
  description: string;
  thumbnail: string;
  demoUrl?: string;
  githubUrl?: string;
  pages: BookPage[];
};

type BookTemplate = {
  id: BookType;
  status: 'ready' | 'placeholder';
  coverColor: string;
  pageColor: string;
  textColor: string;
  accentColor: string;
  roughness: number;
  metalness: number;
  // 素材アセット、装飾描画関数、共通レイアウト設定を保持する。
};
```

type-1を今回の黒い本として完成させる。他の3種類は差し替え可能な登録枠とし、デザイン完成扱いにしない。未制作テンプレートはtype-1の安全な代替表示を使う。

BookPageは編集用の本文データとする。長い文章は表示サイズとフォント計測に基づいて複数の物理ページへ分割する。本文が長くても切り捨てず、生成結果は元のpage idと分割番号で識別する。左右見開きのページ数が合わない場合は黒い空白ページを補う。

idの重複、空タイトル、不正なテンプレート、URLの形式を読み込み時に検証する。URLはhttp/httpsに限定し、未指定のリンクは描画・クリック領域とも生成しない。壊れたサムネイルには代替画像を表示する。

## 9. 状態とアニメーション

| 状態 | 表示 | 許可する主な操作 | 完了後 |
| --- | --- | --- | --- |
| browsing | 斜めのカルーセル | 選択、左右スワイプ | focusing |
| focusing | 正面へ回転・移動 | 背景からの終了要求を記録 | focused |
| focused | 大きな閉じた本 | リンク、表紙を開く、終了 | opening / returning |
| opening | 表紙を開く | 終了要求を記録 | reading |
| reading | 黒い見開き | ページめくり、終了 | reading / closing |
| closing | 紙と表紙を閉じる | 追加の終了要求を無視 | returning |
| returning | 元の位置へ復帰 | 新規の操作を抑制 | browsing |

ページめくりはreading内の補助状態として、idle・dragging・settlingを持つ。同時に複数のページをめくらない。focusedから背景をクリックした場合は、表紙を開いていないためclosingを省略する。

終了要求がページ操作中に来た場合はpointer captureを解放し、ページを有効な位置へ戻す、またはめくりを完了してから閉じる。未完了の骨格姿勢を残したまま表紙を閉じない。

状態管理にはselectedProjectId・carouselIndex・currentSpread・transitionId・pendingExitを保持する。アニメーション完了通知はtransitionIdと照合し、古い完了処理で現在の状態が書き換わらないようにする。移動と開閉の時間は仮設定として調整し、完了判定を固定のsetTimeoutだけに依存させない。

## 10. 本を大きく画面内へ収める設計

### 10.1 表示方針

デスクトップのfocusedでは、余白を含めて収まる場合、本の高さをビューポートの80〜90%程度にする。横幅が先に制約になる場合は横幅を優先し、縦横比と四隅の可視性を保つ。モバイルでは高さ比率を強制しない。

本の3D寸法は固定し、主にカメラ距離・注視点でフィットさせる。状態ごとに本の倍率とカメラ距離を無関係に変更しない。FOVは自然な遠近感のための共通値とし、正確な値は見た目を確認して決める。

### 10.2 フィット計算

Canvasの実際のCSS寸法をW・H、上下左右の予約余白を差し引いた利用可能寸法をWa・Haとする。グローバルナビ・操作バー・safe-areaを余白へ含める。

正面を向いた本の外接寸法をw・h・t、カメラの垂直FOVをθとすると、水平FOV φは次式で求める。

```text
φ = 2 × atan(tan(θ / 2) × W / H)
qx = Wa / W
qy = Ha / H
distance >= max(
  w / (2 × tan(φ / 2) × qx),
  h / (2 × tan(θ / 2) × qy)
) + t / 2
```

角度はラジアンで扱う。これはカメラと本が平行な正面姿勢の初期計算とする。非対称な余白がある場合は、利用可能領域の中心へ投影位置を補正する。

回転中・開いた見開きでは、閉じた表紙の幅だけで計算しない。骨格変形も考慮した保守的な境界、または変形後の頂点から境界を求め、カメラ空間・NDCへ投影して四隅とページ端が収まるか確認する。必要な距離を追加調整し、開いた直後に左右が切れる現象を防ぐ。

リサイズ・画面回転・コンテナ寸法変更時に再計算する。readingでは見開き全体と操作領域を収める別のフィットを使う。画面が狭く本文が読みにくい場合の追加拡大・単ページ表示は今後の検討事項とし、初期版では小画面でも読める本文量と文字サイズを優先する。

## 11. 表紙コンテンツとクリック判定

表紙素材・動的コンテンツ・操作判定を論理的に分離する。素材は再利用可能なテクスチャ、文字・サムネイルはプロジェクトデータ由来のCanvas描画、クリック領域はレイアウト計算結果で管理する。

初期の推奨は、素材とコンテンツをCanvas上で合成した色マップを表紙へ適用し、roughness・normalを別に与える方法である。情報入り画像を手作業で固定するのではなく、データ変更により再生成する。独立したオーバーレイメッシュが必要な場合は面間のちらつきと影を確認する。

coverLayoutは描画矩形とDemo・GitHub・Open bookの領域を同時に返す。RaycasterのヒットUVをCanvas座標へ変換して判定する。UV上下反転は実装で統一し、描画とクリックの座標を別々に手書きしない。

操作優先順位は「ドラッグ判定 → リンク → 開く → 背景」とする。browsing中の表紙クリックは選択だけを行い、同じクリックをfocusedの開く処理へ引き継がない。リンクはfocused時のみ有効とし、処理後は伝播を止める。外部リンクはユーザー操作の同期処理で開き、別タブにはnoopener・noreferrerを適用する。

## 12. ページめくり設計

紙は幅方向に分割したジオメトリと骨格を持つSkinnedMeshで構成する。背側を固定し、先端ほど動くようにskinIndex・skinWeightを与える。紙の向きと湾曲量をめくり進捗から計算する。

表裏はそれぞれの本文テクスチャを持ち、厚み付きのメッシュで面ごとに素材を割り当てる構成を第一案とする。裏面は裏返して読める正しい向きのUVを使う。文字は紙のテクスチャとして描くため、骨格変形に追従する。

ドラッグ開始は外側のページ端に限定する。pointer captureで追跡し、pointercancel・画面外・タッチ中断でも確実に解除する。移動量を本のローカル座標へ変換し、進捗を0〜1に制限する。離した位置と速度から、めくり完了または元に戻す動きを選択する。

透明な紙を重ねず、depthTest・depthWriteを有効にし、紙厚・ページ間隔・骨格の最大角度を調整して貫通を抑える。変形後の境界を更新して、レイキャストやカリングが古い境界に依存しないようにする。

## 13. 入力・アクセシビリティ・表示失敗への対応

クリックとドラッグの判別はCSSピクセルで行い、仮の開始閾値を8pxとする。pointerdownした対象・移動距離・操作開始時の状態を記録し、ドラッグ後のclickで本を開かない。背景で開始・終了したクリックだけを終了操作に使う。

ページ全体の縦スクロールとカルーセルの横操作を分ける。カルーセルではtouch-action: pan-y等を候補として実機確認し、読書中に横ドラッグを使う領域だけ必要な制御を行う。ページ全体へ恒常的にスクロール禁止をかけない。

推奨として、HTML側に作品一覧・リンク・開く／戻る・ページ移動ボタンを提供し、キーボードでも操作可能にする。Canvas内の文字選択は不要だが、作品名と主要リンクは読み上げ可能にする。prefers-reduced-motionでは移動量や時間を抑える。

WebGL初期化失敗・コンテキスト喪失時には、作品名・説明・リンクを持つHTML一覧へフォールバックする。画像・フォント読込失敗で画面全体が停止しないようにする。

## 14. テクスチャと性能

フォントの読み込み完了を待ってから文字を計測・描画し、暫定フォントの配置を完成状態としてキャッシュしない。日本語の禁則・改行、長い英単語、改行文字も扱う。素材は原則として自サイト配信し、外部画像を使う場合はCORSを確認する。

キャッシュキーにproject id・内容バージョン・template id・解像度・フォント設定を含める。データやテンプレートが変わった場合のみ再生成する。生成後にCanvasを書き換えたときはtexture.needsUpdateを更新する。

全作品の全本文ページを高解像度で常駐させない。選択本・表示中の見開きと前後のページを優先し、不要なページテクスチャはキャッシュ上限に従って解放する。共有素材は参照を管理し、使用中にdisposeしない。アンマウント時にgeometry・material・textureを適切に破棄する。

初期の品質案：PCの表紙は高さ2048px程度、モバイルは1024px程度から調整する。紙の比率を維持し、4Kテクスチャを無条件に増やさない。DPRには上限を設ける。隣の本は簡略化した紙束で表示し、本文の骨格を全冊同時に動かさない。

性能目標はPCで滑らかな操作、モバイルで安定した操作とし、暫定目安をPC 60fps・モバイル30fps以上とする。端末とブラウザを記録して評価し、保証値とはしない。影・ポストエフェクト・骨の数は計測を見て調整する。

## 15. 実装順序

1. 既存ソース・package.json・lockfile・AGENTS.mdを読み、現状の起動・ビルドと操作を記録する。
2. 作品データ・テンプレート・状態遷移の責務を整理し、既存コンポーネントへ対応づける。
3. 閉じた本の正面表示とビューポートフィットを先に完成させる。
4. type-1の表紙・背表紙・紙束・ライトを整え、参考画像と比較する。
5. 動的な表紙生成、UVリンク判定、Open bookを接続する。
6. 黒い本文テクスチャ、表裏、ページめくりを統合する。
7. 背景からの復帰・遷移中の入力・ドラッグ中断を安定させる。
8. PC・モバイルの表示と性能、型チェック・ビルドを確認する。
9. 変更ファイル、検証結果、未確定事項と残課題を報告する。

## 16. 完了条件と検証

| 検証対象 | 合格条件 |
| --- | --- |
| 型・ビルド | 既存の型チェックとNext.jsビルドが成功する |
| 正面のサイズ | 幅に余裕があるPCで高さ80〜90%程度。全四隅と必要な余白が見える |
| リサイズ | 横長・縦長・画面回転で表紙や見開きが欠けない |
| カルーセル | 中央が大きく、左右の本が識別でき、スワイプ後に誤クリックしない |
| 選択 | 正面で閉じたまま停止し、自動で開かない |
| リンク | 正しいURLを開き、本は開かない。未設定リンクは判定領域もない |
| 開閉 | Open book・表紙余白で開き、背景で閉じて一覧へ戻る |
| 紙 | 表・裏・端・めくり中まで黒系で、本文が読める |
| ページ操作 | 次・前・先頭・末尾・キャンセルで状態が破綻しない |
| 排他制御 | 連打・ドラッグ直後・遷移中の背景クリックで本が固まらない |
| コンテンツ | 長いタイトル・日本語・長文・画像読込失敗でレイアウトが破綻しない |
| 再利用性 | データ追加だけで作品を追加でき、4種類の登録枠がある |
| 代替操作 | キーボードとHTML側のリンク・戻る操作が利用できる |

画面サイズの初期テスト例は1440×900、1280×720、390×844、360×800 CSS pxとする。各サイズで一覧・正面・見開きを撮影し、サイズ、素材、本文の可読性を比較する。スクリーンショットだけで操作成功と判定せず、リンク・ドラッグ・復帰は実際に操作して確認する。

自動テストは、フィット計算・レイアウトとヒット領域の一致・不正な状態遷移の拒否・主要操作フローなど、破綻すると影響が大きい部分へ絞る。実機未確認のものは確認済みと記載しない。
