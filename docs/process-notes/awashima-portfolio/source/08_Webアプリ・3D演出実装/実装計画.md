# 08 Webアプリ・3D演出実装：実装計画

## 目的

Figmaで画面と導線を整理し、3Dキャラクターを別工程で制作・検証したうえで、Webポートフォリオへ統合する。

## 全体の進め方

```text
準備・判断
   ↓
段階1：Figmaで画面・導線を設計
   ↓
段階2：3Dキャラクターを制作・技術検証
   ↓
段階3：Webアプリへ統合
   ↓
段階4：演出・アクセシビリティ・性能を検証
```

## 段階ごとの役割

| 段階 | 主な目的 | ここで決めること | 次へ進む条件 |
| --- | --- | --- | --- |
| 1. Figmaデザイン | 画面と情報の流れを成立させる | レイアウト、文字、ボタン、本棚、キャラクターの位置 | 3Dなしでも画面と導線を説明できる |
| 2. 3D制作・検証 | キャラクターをWebで使える形にする | モデリング方法、見た目、容量、表示方式 | ブラウザで簡易モデルを表示できる |
| 3. Web統合実装 | Figmaの導線と3Dを一つの体験にする | HTML/CSS/JS、3Dの配置、状態切り替え | ProfileからContactまで通常操作できる |
| 4. 検証・改善 | 演出が情報到達を邪魔しないようにする | Reduced Motion、代替表示、速度、PC幅 | 3Dなしでも利用でき、公開前の問題が整理される |

## 重要な原則

- Figmaは画面全体、情報、導線を設計する場所
- 3DはFigmaで完全再現せず、3Dツールとブラウザで見え方を検証する
- 3Dがなくても、文字・ボタン・リンクだけで主要操作が成立するようにする
- 3D制作は最初から完成品を目指さず、簡易モデルで技術検証してから作り込む
- AIチャット、会話機能、キャラクタークリックによる会話は実装しない

## フォルダの使い方

- `01_画面設計_Figma/`：Figmaで決める画面、状態、コンポーネント、デザイン判断
- `02_3D制作_技術検証/`：Blender / Spline等の調査、簡易モデル、Web表示検証
- `03_Web統合実装/`：HTML / CSS / JavaScriptと3Dの統合実装
- `04_検証_改善/`：操作、アクセシビリティ、性能、演出の検証結果
- `知識/`：工程を通して学んだこと、未解決の疑問、参考資料
