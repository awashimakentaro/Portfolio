# Figma AI用プロトタイプ生成プロンプト

## 使い方

以下の「Figma AIに貼り付けるプロンプト」全体を、Figma AIのプロトタイプ生成機能に貼り付ける。最初の生成では、仮画像・静的モック・簡易インタラクションでよい。3Dキャラクター、音声、複雑なページめくりの実装は後回しにし、まず主要導線と情報の読みやすさを確認する。

## Figma AIに貼り付けるプロンプト

```text
PC向けの個人ポートフォリオサイトの操作可能なプロトタイプを作成してください。

目的：
プロフィール、制作物、インターンシップ経験、連絡先を、黒背景・白文字のサイバー感のある世界観で、1ページのスクロール体験として伝える。作品と経験を「本棚」にまとめ、ユーザーが本を選び、表紙を確認し、本を開いて詳細を読む流れを試せるようにする。

重要な優先順位：
1. Profile → About Me → 本棚（Works / Internship） → Contact の順に、1ページ内をスクロールできること
2. 本棚から本を選ぶ → 本の表紙を見る → 「詳細を見る」 → 本が開く → 詳細を読む → 本棚へ戻る、という主要導線
3. WorksとInternshipの情報構造が区別できること
4. キャラクターがプロフィールから本棚、Contactへ役割を変えること
5. 文字情報と通常のボタンだけでも操作・閲覧できること
6. 上記が成立した後に、ホバー、揺れ、ページめくりなどの演出を加えること

制作上の前提：
- 最初は仮画像、プレースホルダー、静的モックでよい
- 添付の手描きキャラクターは将来3D化する予定だが、今回は仮の2Dイラストまたはシンプルなキャラクターシルエットで表現する
- 3D、音声、効果音、複雑な物理演算は作らず、後から置き換え可能な仮表現にする
- 1回の生成で作りやすいよう、画面は必要最小限のコンポーネントで構成する
- スマートフォン版は今回の対象外。PC幅のプロトタイプを優先する

ビジュアル方針：
- 全体は黒背景、白文字を基本にする
- アクセントカラーは1〜2色まで。ネオン系の青、緑、または紫を少量だけ使い、本文の可読性を損なわない
- 画面上部に黒背景の固定グローバルナビゲーションを配置する
- 左に「AK」ロゴまたは名前、右に「Profile」「Works」「Internship」「Contact」を配置する
- ナビゲーションの文字は読みやすい大きさにし、余白を十分に取る
- 装飾を増やしすぎず、プロフィールの文字、本棚、本の情報が主役になるようにする
- カーソルの背後や周辺に追従するイラストは表示しない

作成するフレーム／状態：

【A. トップ・Profileファーストビュー】
- 画面全体を使った最初のセクション
- 左側に名前を大きく表示する。仮文言は「AWASHIMA」または「Awa Shima」
- 中央にキャラクターの上半身の仮画像を大きく配置する
- 右側に「Software Engineer」「UI Designer」を表示する
- セクション名として「Profile」を配置する
- 画面下部にスクロールを促す小さなテキストを置く
- ナビゲーションのProfile / Works / Internship / Contactは、トップでは選択状態にしない

【B. Profile / About Me】
- 左にAbout Meの見出しと文章、右にキャラクターを配置する
- 文章には仮の項目として、趣味、学校・専攻、これまでやってきたこと、興味のある分野、目指していることを含める
- 筋トレを趣味の例として表示し、キャラクターの横に小さなダンベルやポーズの仮表現を置く
- キャラクターはファーストビューより右側へ流れたように見せる
- 重要情報は文章として読めるようにし、キャラクターの吹き出しだけには依存させない

【C. 本棚セクションの初期状態】
- Profile終了後に続く、WorksとInternshipをまとめた1つの本棚
- 本棚は最初から表示する。ロード後に突然出現させない
- 本棚の左または中央に、区画名「WORKS」「INTERNSHIP」を明確に表示する
- WORKSの中に「AGENT」「APPS」「DESIGN」の3分類を設ける
- 各分類に本の形をした作品カードを2〜3冊ずつ仮配置する
- INTERNSHIPの区画にも、インターンシップを1冊ずつ仮配置する
- 本の背表紙には短いタイトルを表示し、色や装飾で分類を区別する
- 本棚の右側に小さくなったミニマムキャラクターを配置する
- キャラクターの吹き出しには「ここから選んでね」などの短い案内を表示する
- ミニマムキャラクターは本棚の案内役としてのみ使用する。AI機能、会話機能、入力欄、チャットボタンは作らない
- キャラクターがなくても、本の分類と選択方法が理解できるようにする

【D. 本をホバーした状態】
- 本をマウスオーバーすると、その本だけが少し浮き上がる、または数度だけ軽く揺れる
- 他の本は動かさない
- タイトルまたは「選択できます」が分かる視覚的な状態を付ける
- ホバーを外すと元の位置へ戻る

【E. Worksの本の表紙状態】
- 本棚で作品をクリックすると、同じページ内で選択した本が手前に出て表紙を表示する
- 背景に本棚を薄く残し、現在地が分かるようにする
- 表紙には、作品名、サムネイルの仮画像、短い概要、区分名を表示する
- 「詳細を見る」「デモを見る」「GitHubを見る」「本棚へ戻る」のボタンを配置する
- 使用技術、制作期間、担当内容は表紙の主情報に詰め込みすぎず、詳細ページ側に置く
- 「詳細を見る」を押すとWorks詳細状態へ進む
- 「本棚へ戻る」を押すと本棚の初期状態へ戻る

【F. Works詳細状態】
- 表紙から本が開くように見える簡易な遷移を設定する
- ページめくりは、2〜3枚の白または暗色のページが短く切り替わる仮演出でよい
- 演出後に、同じページ内で作品詳細を表示する
- 詳細には次の順番で情報を配置する：
  1. 作品情報（作品名、概要、制作期間、担当、使用技術）
  2. Context（背景・課題・目標）
  3. Process
  4. Review（検証と改善）
  5. Outcome（成果・効果）
  6. 学んだこと
  7. Tools（使用ツール・使用技術）
- 「前の作品」「次の作品」「表紙へ戻る」「本棚へ戻る」を用意する
- 作品詳細、デモ、GitHubの導線を別々のボタンとして表示する

【G. Internshipの本の表紙状態】
- 本棚のINTERNSHIP区画から本をクリックすると、選択した本の表紙を表示する
- 表紙には会社名、インターンシップ名、在籍期間、担当領域・役割、短い概要を表示する
- 「詳細を見る」「本棚へ戻る」を配置する

【H. Internship詳細状態】
- Works詳細と同じく、本が開いてページをめくる簡易演出の後に詳細を表示する
- 詳細には次の情報を順番に配置する：
  1. 会社名
  2. インターンシップ名
  3. 在籍期間
  4. 担当領域・役割
  5. 業務内容
  6. 実施したこと
  7. 改善・工夫
  8. できるようになったこと
  9. 苦労
  10. 学び
  11. 今後に生かしたいこと
- 「前のインターンシップ」「次のインターンシップ」「表紙へ戻る」「本棚へ戻る」を用意する
- ページめくりがなくても、通常の縦スクロールとボタンで内容を読めるレイアウトにする

【I. 本棚の案内役キャラクター】
- 本棚右側に小さなミニマムキャラクターを固定または静かに配置する
- 吹き出しには「ここから選んでね」など、本の選び方を伝える短い案内だけを表示する
- キャラクターをクリックしてもAI会話やチャット画面は開かない
- キャラクターがなくても、本棚の分類、本の選択、Contactへの導線が使えるようにする

【J. Contactセクション】
- ページ終盤にContactセクションを配置する
- 見出し「Contact」を大きく表示する
- キャラクターを案内役として配置し、吹き出しに「連絡してね」「気軽に話しかけてね」などの仮文言を表示する
- メールアドレス、メールを送るボタン、必要に応じたSNS・外部リンクを通常のテキストリンクとして表示する
- 本棚の案内役と通常のContact導線を混同しないようにする
- キャラクターがなくても、見出しとリンクだけで連絡先が分かるようにする

画面遷移とプロトタイプ接続：
- AKをクリックするとページ先頭へ戻る
- ProfileをクリックするとProfileの先頭へスクロールする
- Worksをクリックすると本棚のWORKS区画へスクロールする
- Internshipをクリックすると本棚のINTERNSHIP区画へスクロールする
- ContactをクリックするとContactへスクロールする
- 各ナビゲーションは同一ページ内のアンカー遷移として表現する
- 本棚の本をクリックすると、その本の表紙状態へ遷移する
- 表紙の「詳細を見る」をクリックすると、対応する詳細状態へ遷移する
- 詳細から「表紙へ戻る」をクリックすると表紙へ戻る
- 表紙から「本棚へ戻る」をクリックすると本棚へ戻る
- 同一分類に複数の本がある場合は、「前へ」「次へ」または左右矢印で切り替えられるようにする
- Contactのメールリンクは仮リンクでよいが、通常のリンクとして見えるようにする

仮アニメーション：
- ページロード時は、文字とキャラクターを短くフェードインする程度にする
- ナビゲーションのホバーでは、ホバーされた文字だけが横方向に弧を描くようにゆっくり揺れる。カーソル周辺にイラストは表示しない
- ProfileからAbout Meへスクロールすると、キャラクターが中央から右側へ移動したように見せる
- Profile終了後、本棚に入るとキャラクターを小さくし、本棚右側へ移動した状態を見せる
- 本棚の本はホバー時だけ少し浮き上がる。自動で激しく動かさない
- 本の表紙表示は、選択した本が手前に出る短いズームまたはフェードでよい
- 詳細表示は、短いページめくりの仮演出後に表示する
- Contactではキャラクターを静かに案内役として表示する
- すべての演出は短く、情報の到達を遅らせない

アクセシビリティと代替状態：
- prefers-reduced-motionを想定した「アニメーションなし」状態を作る
- アニメーションなしでは、ページめくり、キャラクター移動、揺れ、浮き上がりを停止し、即時切り替えにする
- キャラクターや仮画像が読み込めない場合も、代替テキストまたはプレースホルダーと文章で情報を読めるようにする
- 吹き出しだけに重要情報を置かない
- キーボードフォーカスが見える状態を、各リンク、ボタン、本に設定する
- フォーカス時は色の変化だけに頼らず、アウトラインまたは枠線でも示す
- 本の選択、表紙、詳細、Contactを通常のボタン・リンクとして操作できるようにする
- 白文字と背景のコントラストを十分に確保する
- 本の詳細ページには、ページめくりがなくても読める静的な本文を用意する
- ミニマムキャラクターの吹き出しは補助情報として扱い、非表示にしても主要導線が残るようにする

プロトタイプの検証用に、次の状態・バリエーションも作成する：
1. 演出あり：ホバー、キャラクター移動、表紙ズーム、簡易ページめくりを表示
2. 演出を減らした状態：フェードと短い切り替えだけを表示
3. 演出なし：すべて即時切り替え。文章、ボタン、リンクだけで成立

まずはA〜C、E、F、Jの主要画面と接続を優先して生成する。次にD、G、H、Iを追加し、最後に仮アニメーションとアクセシビリティ用の状態を追加する。完成度よりも、Profileから本棚を経由して作品・経験を読み、Contactへ到達できることを優先する。
```

## 生成後に確認する項目

- ナビゲーションからProfile、Works、Internship、Contactへ迷わず移動できるか
- 本棚が最初から見えており、WorksとInternshipの区画が区別できるか
- 本を選択した後に、いきなり詳細へ飛ばず表紙を確認できるか
- 表紙 → 詳細 → 表紙 → 本棚の戻り方が分かるか
- Works詳細とInternship詳細の項目が混ざっていないか
- ミニマムキャラクターを非表示にしても本棚と通常リンクが使えるか
- キャラクターやアニメーションがなくても、情報と主要導線が成立するか
- 演出がユーザーの情報到達を遅くしていないか
- マウスホバーを使えない場合も、フォーカスとクリックで操作できるか
- Contactで本棚の案内役と通常の連絡先が混同されないか

## 今回のプロトタイプで未確定のままにするもの

- キャラクターの最終的な3Dモデル、表情、視線追従の精度
- 本の最終的な材質、表紙デザイン、棚の造形
- アクセントカラーの最終決定
- ページめくりの実装方法と速度
- 音声、効果音、会話機能の実装
- 実際の作品データ、会社名、メールアドレス、外部リンク
- スマートフォン版のナビゲーションとレイアウト
