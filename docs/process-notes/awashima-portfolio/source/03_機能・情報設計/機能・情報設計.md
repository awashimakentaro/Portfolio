# awashima-world 機能・情報設計

## 1. この設計の目的

「企画・要件定義（最終版）」で定めた目的と優先順位を、サイトに必要な機能、掲載情報、ページ構成へ変換する。

最優先するのは、採用担当者が短時間で次の情報を理解できることである。

- 何を目指している人か
- 何ができる人か
- 代表作品は何か
- 各作品で何を担当したか
- どんな成果が出たか
- 詳細や連絡先へどう進めるか

## 2. 設計原則

1. 要約を先に出し、詳細は必要な人が深掘りできるようにする
2. 作品ごとの情報順を統一し、比較しやすくする
3. 作品・デモ・GitHubへ直接移動できるようにする
4. 演出は個性を伝える補助とし、情報・操作・速度を優先する
5. 調査で確認できたことと、まだ仮説のことを区別する
6. ページや機能を増やすこと自体を目的にしない

## 3. サイトマップ

```text
トップページ /
├─ プロフィール /about
├─ インターンシップ一覧（トップページ内） /#internships
│  └─ インターン先詳細 /internships/[id]
├─ 作品一覧（トップページ内）
│  ├─ awashima-world 詳細 /works/awashima-world
│  │  └─ 制作姿勢・制作過程（Process）
│  ├─ ダイエットアプリ 詳細 /works/diet-app
│  ├─ 学校課題を自動化するエージェント 詳細 /works/agent
│  └─ Presence Note 詳細 /works/presence-note
└─ 連絡先・GitHub（トップページ下部のフッター）
```

### ページ化の判断

- トップページには、判断に必要な要約と主要導線を置く
- 作品詳細は、作品ごとの課題・プロセス・成果・学びを同じ構成で置く
- インターンシップ一覧はトップページ内に置き、グローバルナビゲーションから直接移動できるようにする
- 本人の担当範囲は、各インターン先の詳細ページで確認できるようにする
- 制作姿勢・制作過程（Process）は独立ページにせず、`awashima-world` の作品詳細内に含める
- Aboutは、人物像・得意領域・制作姿勢を深掘りするページとして扱う
- メールアドレスとGitHubはトップページ下部のフッターに配置する

## 4. 主要ユーザーフロー

### フローA：採用担当者が代表作品を確認する

```text
トップページ
  ↓ ファーストビューで職種・強みを把握
代表作品への導線
  ↓
作品一覧
  ↓ 作品名・何を作ったか・GitHubリポジトリURL・デモURLを確認
作品詳細
  ↓
プロセス・成果・学びを確認
  ↓
必要に応じてInternshipsから担当範囲を確認
  ↓
GitHubリポジトリ / デモ / トップページ → フッターのメール
```

### フローB：制作姿勢を確認する

```text
トップページ
  ↓
awashima-world 詳細
  ↓
企画 → 要件定義 → デザイン → 実装 → 公開・改善
  ↓
制作メモ（GitHub）
```

### フローC：個性や人柄を知る

```text
トップページ
  ↓
キャラクター・About・淡嶋AI
  ↓
プロフィール / 人柄 / 考え方 / 制作物
  ↓
作品詳細またはフッターのメール
```

フローCは補助導線であり、淡嶋AIや演出がなくてもフローAが成立する必要がある。

## 6. 掲載情報の設計

### 6.1 トップページ

| 情報 | 目的 | 優先度 |
| --- | --- | --- |
| 志望職種・立場 | 評価の軸を明確にする | Must |
| 強み | 何ができる人かを伝える | Must |
| 中心メッセージ | 人物像と制作姿勢を伝える | Must |
| 代表作品 | 最初に見たい情報へ誘導する | Must |
| 作品一覧 | 作品名、概要、GitHubリポジトリ、デモ、詳細への導線を確認する | Must |
| Internshipsへの導線 | 実務経験・担当範囲を直接確認する | Must |
| Aboutへの導線 | 経歴・人柄を深掘りしてもらう | Should |
| キャラクター | 個性を伝える | Should |
| 淡嶋AIへの導線 | 回遊と自己紹介を促す | Should |
| フッターのメール・個人GitHub | 連絡や活動全体の確認につなげる | Must |

### 6.2 作品一覧

すべての作品で、表示する情報の種類と順番を揃える。

| 情報 | 内容 |
| --- | --- |
| 作品名 | 作品を識別できる名称 |
| 一言概要 | 何を作ったか |
| GitHubリポジトリURL | 作品のソースコードや制作内容を確認するリンク |
| デモURL | 実際に動く作品を確認するリンク |

### 6.3 作品詳細

作品詳細は、次の順番を標準構成とする。

1. 作品名・一言概要
2. 課題・背景
3. 目標
4. 想定ユーザー・利用者
5. 制作プロセス
6. 判断・工夫したことと理由
7. 検証・改善内容
8. 成果・効果
9. 使用技術・ツール
10. GitHub・デモ・成果物リンク
11. 今後の改善点・学び
12. 次の作品・Internshipsへの導線

情報量が多い作品では、1〜4を要約として先に表示し、5以降を詳細として段階的に読めるようにする。

### 6.4 awashima-world詳細

この作品だけは、制作過程そのものを中心に表示する。

```text
企画
  ↓
要件定義
  ↓
デザイン
  ↓
実装
  ↓
公開・改善
  ↓
改善
```

各工程では、サイト内に概要を掲載し、詳細な制作メモはGitHubへリンクする。

### 6.5 Internships

- グローバルナビゲーションからトップページ内のインターンシップ一覧へ移動できる
- 一覧には、インターン先名、在籍期間、職種または担当の要約、詳細ページへの導線を表示する
- 各詳細ページには、在籍期間、担当範囲、実際に行ったこと、関連する制作内容、振り返りを記載する
- 詳細ページから、他のインターン先、関連作品、About、トップページへ移動できるようにする

### 6.6 About / Profile

- 氏名・表示名
- 志望職種
- 経歴
- 得意領域
- デザインと技術の関わり方
- ものづくりへの考え方
- 人柄が伝わる短い情報

最初の画面に必要な要約はトップにも置き、詳しい情報だけをAboutへ分ける。

インターンシップの実務経験や担当範囲を確認したい人には、Internshipsへの導線を用意する。

### 6.7 フッター

- トップページ下部のメールアドレス
- トップページ下部の個人GitHubホームURL
- キャラクターによる案内文（任意）

問い合わせフォームは今回作らず、トップページ下部にメールリンクと個人GitHubホームURLを配置する。

## 8. 要約と詳細の分け方

### 先に見せる情報

- 作品名
- 何を作ったか
- 何の課題を解決したか
- 詳細・デモ・GitHubへのリンク

### 深掘りしたい人向けの情報

- 詳細な背景
- 制作中の判断理由
- 調査・設計・実装の過程
- 検証方法と改善内容
- 失敗、制約、今後の課題

## 9. ナビゲーション設計

- グローバルナビゲーションに、About、Works、Internships、Contactを配置する
- `Internships` はトップページ内のインターンシップ一覧へページ内移動できるようにする
- ProcessはWorksの中の`awashima-world`詳細から案内する
- 作品一覧から作品詳細へ直接移動できる
- 作品一覧からGitHubリポジトリとデモへ直接移動できる
- 作品詳細からGitHubリポジトリとデモへ直接移動できる
- 作品詳細から成果物へ直接移動できる
- インターンシップ一覧から各インターン先詳細へ直接移動できる
- インターン先詳細からInternships、About、関連作品、ポートフォリオへ戻れる
- トップページ下部のフッターからメールアドレスと個人GitHubホームURLへ移動できる
- GitHubやデモなどの外部リンクは新しいタブで開く
- 作品詳細から次の作品、作品一覧、トップページへ移動できる
- ページ内の長い情報には目次またはセクションナビゲーションを検討する
- AIやキャラクターの案内がなくても、ナビゲーションだけで主要導線を完結させる

## 10. 演出・淡嶋AIの扱い

### 残すもの

- メインキャラクターによる個性の表現
- サイトの雰囲気をつくる適度な動き
- 淡嶋AIによるプロフィール・作品紹介

### 制限するもの

- 重要情報をアニメーションの完了まで隠さない
- クリックやページ遷移を遅らせない
- AIの回答だけに、職種・担当範囲・成果などの重要情報を任せない
- 演出を減らしても、サイトの目的と導線が成立するようにする

## 11. 完了基準

### 設計としての完了

- サイトマップがある
- 主要ユーザーフローが整理されている
- 必要機能に優先順位がある
- ページごとの掲載情報が決まっている
- 作品詳細の共通構成が決まっている
- 作品情報の管理項目が決まっている
- 未決定事項と仮説が区別されている

### 次工程へ渡せる状態

- ユーザーフローをもとにワイヤーフレームを作れる
- 各画面に必要な情報と導線を配置できる
- 演出を入れる場所と、入れてはいけない場所が説明できる
- 初期公開に含める機能と後回しにする機能が決まっている

## 12. 未決定・要検証

- ファーストビューの具体的なコピー
- トップページで表示する作品数
- Aboutを独立ページにするか、トップページ内のセクションにするか
- 淡嶋AIを初期公開に含めるかどうか
- キャラクターのアニメーション量と速度
- 作品詳細の折りたたみ・タブ・ページ分割の方式
- 実際のユーザーが、要約だけで評価に必要な情報を得られるか

これらはワイヤーフレームとプロトタイプで確認する。

## 13. 3D・演出を含む機能と情報の分離

3Dキャラクター、アニメーション、音声、効果音、ホバーやスクロールへの反応は、情報設計上の主要情報とは分けて扱う。

- 必ず表示する情報：職種、強み、作品、担当範囲、成果、導線、連絡先
- 演出で補助する情報：案内、雰囲気、人柄、操作のフィードバック
- 後回しにできるもの：高度な演出、複雑な音声会話、装飾的なエフェクト

演出を無効化しても、ナビゲーションと主要情報だけで目的を達成できる構造にする。演出の状態や反応の詳細は04で設計し、見た目は06、操作可能な検証は07、実装方法は08で扱う。
