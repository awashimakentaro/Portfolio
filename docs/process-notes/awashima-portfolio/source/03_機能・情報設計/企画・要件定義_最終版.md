# awashima-world 企画・要件定義（最終版）

## 0. この文書の位置づけ

この文書は、既存の「企画・要件定義」と「調査結果・課題整理」をもとに、現時点の企画と要件を整理し直した最終版である。

ユーザー調査は回答4件（うち1件は仮想ペルソナによる合成回答）であるため、以下の内容は確定した市場調査結果ではなく、次の制作・検証へ進むための現時点の要件と仮説として扱う。

## 1. プロジェクト概要

`awashima-world` は、UI/UXデザイナーを目指す淡嶋の考え方・制作物・制作プロセスを伝える、日本語のインタラクティブなポートフォリオサイトである。

制作物を並べるだけではなく、企画、要件定義、デザイン、実装、公開後のフィードバック、改善までを、UI/UXデザインとエンジニアリングの実践例として見せる。

## 2. 目的

### 2.1 サイトの目的

- 採用担当者が短時間で、淡嶋の志望職種・強み・代表的な成果を理解できるようにする
- 作品ごとに、課題、本人の担当範囲、制作プロセス、成果を確認できるようにする
- UI/UXデザインと実装の両方に取り組めることを伝える
- 面白い発想を実際に動く形へ落とし込めることを伝える
- 公開後の意見を収集し、改善まで行う姿勢を示す
- キャラクターや演出によって人柄・個性を伝える。ただし、情報理解と閲覧速度を妨げない範囲にする

### 2.2 ユーザーが達成したいこと

採用担当者や協業相手が、短時間で次のことを判断できる状態を目指す。

1. この人は何を目指し、何ができるのか
2. 代表作品は何か
3. 作品の中で本人は何を担当したのか
4. どのような課題に対して、どう考え、何を作ったのか
5. 成果や実績を確認できるか
6. さらに詳しく見る、連絡する、といった次の行動へ進めるか

## 3. 想定ユーザーと優先順位

| 優先度 | ユーザー | 目的 |
| --- | --- | --- |
| 1 | UI/UXデザイン会社の面接官・採用担当者 | デザイン力、課題解決力、担当範囲、成果を短時間で評価する |
| 2 | エンジニア採用担当者 | 実装力、技術理解、制作物の具体性を確認する |
| 3 | 協業候補者・制作関係者 | 人柄、得意領域、制作姿勢、連絡先を確認する |

## 4. 中心メッセージ

> 変わったアイデアでも、実際に動くものとして形にしてみる。かわいく、楽しく、使う人の体験まで考えながら作る。

このメッセージを、次の3点に分けて伝える。

- **考える**：ユーザーや課題を考えて企画・設計する
- **つくる**：デザインと技術を使って実際に形にする
- **改善する**：公開後の反応を受けて見直す

## 5. 解決する課題

### 最優先の課題

採用側がポートフォリオを短時間閲覧したときに、本人の志望職種・強み・代表的な成果・各作品での担当範囲を把握できず、実務能力を評価しにくい。

### 関連する課題

- ファーストビューで「何ができる人か」が分かりにくい
- 作品の成果と本人の担当範囲が分かりにくい
- 作品ごとの情報構成が揃っておらず、比較しにくい
- 情報量が多く、重要な情報に到達するまでの負荷が高い
- アニメーションや演出が、閲覧速度を下げる可能性がある
- 作品、デモ、リポジトリへ直接移動しにくい可能性がある

## 6. 提供する解決方針

- ファーストビューで、志望職種・強み・代表実績を明確に伝える
- 代表作品を早い段階で見つけられるようにする
- 作品詳細の構成を統一し、課題・役割・プロセス・成果を同じ順番で表示する
- 要約を先に、詳細を後に配置し、段階的に読めるようにする
- GitHub、デモ、成果物などの外部リンクを作品ごとに直接配置する
- キャラクターやアニメーションは個性を伝える補助として扱い、操作や読解を妨げないようにする

## 7. コンセプト・ビジュアル方針

- 自分に関係するオリジナルキャラクターをメインキャラクターとして使用する
- かわいい、少し変わっている、不思議、近未来的な印象をつくる
- モノトーンを基調にし、ファンシーだが子どもっぽくなりすぎない表現にする
- 自作のキャラクターやイラストを使用する
- 演出は、情報の優先順位と読みやすさを保ったうえで使用する

## 8. サイトの主要構成

```text
トップページ
├─ About / Profile
├─ Internships（トップページ内の一覧）
│  └─ インターン先詳細 /internships/[id]
├─ Works（制作物一覧）
│  ├─ awashima-world 詳細
│  │  └─ Process（制作姿勢・制作過程）
│  ├─ ダイエットアプリ 詳細
│  ├─ 学校課題を自動化するエージェント 詳細
│  └─ Presence Note 詳細
└─ Contact（メール連絡先・アンケート導線）
```

制作姿勢・制作過程は独立ページにせず、`awashima-world` の作品詳細に含める。インターンシップ一覧はトップページ内に置き、グローバルナビゲーションの `Internships` から直接移動できるようにする。実際のページ数や表示形式は、ワイヤーフレーム作成時に情報量と閲覧負荷を見て確定する。

## 9. 初期掲載する制作物

掲載順は次のとおり。

1. `awashima-world` — このポートフォリオ自体
2. ダイエットアプリ — 食事画像からカロリーを予測し保存するアプリ
3. 学校課題を自動化するエージェント — エンジニアリング面を示す制作物
4. Presence Note — Raspberry Piを使用した制作物

各作品には、少なくとも作品名、サムネイル、概要、本人の担当範囲、成果または学び、詳細ページへの導線を用意する。

## 10. 要件一覧

### 10.1 Must：今回の目的達成に必須

| ID | 要件 | 完了の目安 |
| --- | --- | --- |
| M-01 | ファーストビューで志望職種・強み・代表実績を伝える | 初見の採用担当者が短時間で人物像を説明できる |
| M-02 | 代表作品をトップから直接確認できる | 主要作品へ迷わず移動できる |
| M-03 | 作品一覧に作品名・サムネイル・短い概要を表示する | 作品の違いと優先順位が分かる |
| M-04 | 作品詳細に課題・背景・目標・担当範囲を表示する | 本人の貢献範囲を判断できる |
| M-05 | 作品詳細に制作プロセス・判断理由・検証・成果を表示する | 実務での考え方と結果を確認できる |
| M-06 | GitHub、デモ、成果物などへの直接リンクを用意する | 外部の実物をすぐ確認できる |
| M-07 | 作品詳細の情報構成を統一する | 複数作品を同じ観点で比較できる |
| M-08 | メールアドレスを連絡先として掲載する | 問い合わせ方法が分かる |
| M-09 | PCを主対象とし、スマートフォンでも閲覧できる | 主要情報と導線が両環境で利用できる |
| M-10 | 情報をMarkdownまたはデータファイルで管理する | CMSなしで更新できる |
| M-11 | グローバルナビゲーションからインターンシップ一覧へ直接移動できる | 担当範囲・実務経験を独立した入口から確認できる |

### 10.2 Should：重要だが、Mustの後に調整

| ID | 要件 | 判断理由 |
| --- | --- | --- |
| S-01 | 淡嶋AIでプロフィールや制作物を質問できる | 人柄や回遊性を高めるが、最初の評価に必須ではない |
| S-02 | キャラクターがサイト内の導線を案内する | 個性を伝えられるが、静的な導線でも目的は達成できる |
| S-03 | 制作過程を工程ごとに見られる | awashima-worldの制作姿勢を伝えやすい |
| S-04 | 匿名アンケートへ誘導する | 公開後の改善に使える |
| S-05 | 作品内に「要約」と「詳細」を分けて表示する | 情報量による負荷を下げられる |

### 10.3 Could：余力と検証結果に応じて追加

- 高度なアニメーションやキャラクター演出
- 作品の絞り込み・検索
- A/Bテスト
- AIによる高度な質問応答
- 作品間の関連表示

### 10.4 Won't now：今回の初期公開では扱わない

- CMSの導入
- 会員登録・ログイン
- 問い合わせフォームの独自実装
- 複雑な管理画面
- AIチャットや演出の作り込みを、情報の分かりやすさより先に進めること

## 11. 淡嶋AIの要件

淡嶋AIは、初期公開の中核ではなく、ポートフォリオの個性と回遊性を高める補助機能として扱う。

### 表示・回答する情報

- プロフィール、人柄、経歴
- ものづくりへの考え方
- 制作物、GitHub、デモリンク
- UI/UXデザインへの考え方
- 失敗や学び

### キャラクター性

面白い口調で回答する。ただし、回答内容の正確性とリンク先の分かりやすさを優先する。

### 回答できない場合

「わからぬでござる」「それはまだ解禁されておらぬ」など、キャラクター性を保った返答をする。ただし、重要な採用情報をAI回答だけに依存させない。

### 情報管理

CMSは使用せず、Markdownまたはデータファイルを編集して更新する。

## 12. 技術・運用要件

- Next.jsを使用する
- 日本語のみ対応する
- PCを主な閲覧環境とする
- スマートフォンでも閲覧できるようにする
- CMSは使用しない
- 作品情報と淡嶋AIの情報はMarkdownまたはデータファイルで管理する
- GitHubリンク、作品のデモリンク、メールアドレスを掲載する
- 公開後に匿名アンケートで意見を集め、改善に利用する

## 13. 非機能要件・品質方針

- ファーストビューから主要作品へ移動できる
- 重要情報がアニメーションの完了を待たずに確認できる
- アニメーションを減らしても、情報と導線が成立する
- 作品詳細は、要約を先に確認できる
- 外部リンクのリンク切れを確認する
- 作品ごとの情報が同じ順序で表示される
- キーボード操作、読みやすい文字サイズ、十分なコントラストを考慮する
- モーションを抑えたいユーザーにも配慮する

## 14. 検証計画

### 初期公開前

- 初見の人に、ファーストビューだけで「何をしている人か」を説明してもらう
- 代表作品と問い合わせ先を迷わず見つけられるか確認する
- グローバルナビゲーションからInternshipsへ移動し、担当範囲を確認できるか確認する
- 作品詳細を見て、本人の担当範囲と成果を説明できるか確認する
- アニメーションを見ても、情報到達が遅くならないか確認する
- PCとスマートフォンで主要導線を確認する

### 公開後

- 匿名アンケートで、人物像・分かりやすさ・良い点・改善点を収集する
- 回答を「理解」「操作」「情報量」「演出」「信頼性」に分類する
- 改善前後で、主要情報への到達しやすさと理解度を比較する

## 15. 完了基準

- 最優先ユーザーとサイトの目的が説明できる
- ファーストビューで志望職種・強み・代表実績が伝わる
- 代表作品へ直接移動できる
- 作品詳細で課題・担当範囲・プロセス・成果を確認できる
- 各作品の構成が統一されている
- GitHub、デモ、メールへの導線が機能する
- グローバルナビゲーションからインターンシップ一覧と各インターン先詳細へ進める
- 重要情報が演出に隠れない
- PCとスマートフォンで主要導線が利用できる
- 公開後のフィードバック収集方法が用意されている
