# 02 ユーザー調査・課題整理

## 調査目的

特に、最初に確認される情報、評価に必要な情報、情報不足による不安・離脱理由、awashima.devの改善優先度を明らかにする。

## 回答から分かったこと

### 1. 採用側は、まず代表作品を見て判断を始める

プロフィールや技術一覧よりも、代表的な制作物・プロジェクトを先に確認する傾向が見られた。作品一覧や代表作への導線は、成果まで含めて把握できる構成にする必要がある。

### 2. 技術の多さだけでは実務能力を判断しにくい

課題設定、本人の役割、意思決定、制作プロセス、検証、成果、改善内容がないと、実際の実務能力や貢献範囲を判断しにくい。

### 3. 現在のサイトは個性が伝わる一方、採用向けの要点整理に改善余地がある

キャラクターや配色による個性、継続的な制作活動、技術とデザインの両方への関心は伝わっている。一方で、UI/UXデザイナー志望なのかフロントエンドエンジニア志望なのか、採用側がどの軸で評価すべきか迷う可能性がある。

### 4. 作品ごとの説明形式を統一すると評価しやすくなる

作品ごとに、次の情報を同じ順番で確認できる構成が望ましい。

1. 課題・背景
2. 目標
3. 本人の役割・担当範囲
4. 調査・設計・実装・検証のプロセス
5. 成果・効果
6. 改善点・学び

### 5. 情報量と演出が、理解の負荷や離脱につながる可能性がある

情報量の多さは網羅性として評価される一方、流し読みや未読につながる可能性もある。アニメーションは個性や印象形成に役立つが、遷移を遅くしたり、情報への到達を妨げたりしない設計が必要である。

### 6. 作品や成果へ直接移動できる導線が求められている

採用側は短時間で代表作品や成果を確認したいため、トップページから作品詳細、成果物、リポジトリ、デモなどへ直接移動できる導線が必要である。

## ユーザーの課題

### 課題1：採用側が、最初に「何ができる人か」を把握しにくい

サイトを開いた直後に、志望職種、得意領域、代表的な成果が一目で分からないため、採用側が評価の軸を定めにくい。

### 課題2：作品の成果と本人の担当範囲が分かりにくい

技術や制作物の説明はあるが、ユーザー課題、成果の根拠、本人がどこまで担当したかが十分に整理されていないため、実務能力を判断しにくい。

### 課題3：作品ごとの情報構成が揃っておらず、比較しにくい

作品ごとに確認できる情報の種類や順番が異なるため、採用側が複数の作品を同じ基準で比較しにくい。

### 課題4：情報量が多く、重要な情報に到達するまでに負荷がかかる

技術スタックや文章量が多いため、短時間で確認したい採用側にとって、重要な情報が埋もれる可能性がある。

### 課題5：アニメーションや演出が、閲覧速度を下げる可能性がある

キャラクターやアニメーションは個性を伝える一方、遷移が遅い場合には離脱理由になる可能性がある。演出の効果と閲覧速度のバランスを確認する必要がある。

## 課題の優先順位

1. ファーストビューでポジション・強み・代表成果を伝える
2. 代表作品に課題・役割・成果を追加する
3. ケーススタディの構成を統一する
4. 文章量とナビゲーションを整理する
5. 作品・成果物・デモへの直接導線を追加する
6. キャラクター・ビジュアル表現を、情報理解を邪魔しない形に調整する

## 今回解決する課題

> 採用側がポートフォリオを短時間閲覧したときに、本人の志望職種・強み・代表的な成果・各作品での担当範囲を把握できず、実務能力を評価しにくい。

まずは、ファーストビューで志望職種と強みを明確にし、代表作品と成果への導線を分かりやすくする。各作品では、課題、役割、プロセス、成果を同じ構成で確認できるようにする。

作品詳細、成果物、リポジトリ、デモへの直接導線を用意し、アニメーションは閲覧速度を下げない範囲で使用する。

### 現時点での注意点

回答数は4件と少なく、うち1件は仮想ペルソナによる合成回答である。そのため、現段階の結論は確定的な市場調査結果ではなく、次の設計に進むための仮説として扱う。特に、4件中3件でファーストビューの分かりにくさが指摘された点は、追加調査で確認する価値が高い。今後は実在する採用担当者、デザイナー、エンジニアなどから追加回答を集め、今回の課題が複数の回答者に共通するかを確認する。

## 調査結果の結論

4名への調査から、ポートフォリオでは「成果・効果」「実績の具体性」「制作プロセス・改善内容」が重視されることが分かった。

一方、4名中3名が「最初の画面で何をしている人か分かりにくい」と回答した。文章の読みやすさとナビゲーションにも改善余地がある。

### ユーザーに起きる問題

採用担当者や協業相手は、ポートフォリオを訪れたときに、ファーストビューだけでは職種・強み・代表実績を把握できない。また、各制作物でも本人の担当範囲、課題、制作プロセス、成果が分散しているため、短時間で実務能力を判断しづらい。

### ユーザーが達成したいこと

短時間で候補者の職種・強み・代表的な成果を理解し、制作物から実務能力や担当範囲を判断したい。

### 次の設計で満たすこと

- ファーストビューに職種・強み・代表実績を掲載する
- 制作物ごとに「課題・担当範囲・プロセス・成果」を統一して表示する
- 要約を先に見せ、詳細情報は段階的に読めるようにする
- 作品・デモ・GitHubなどへ直接移動できるようにする
- 文章量とナビゲーションを整理する

### 今回は優先しないこと

AIチャット、複雑なアニメーション、キャラクター演出の作り込みは、今回の最優先課題ではないため、検討案・優先度低として扱う。
