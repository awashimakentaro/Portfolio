# 実践記録

## 2026-10-20：3件の回答から設計仮説を作る

### 使用したデータ

- 回答元：回答データ原本（個別回答の公開範囲が未確認のため、公開用コピーではURLを省略）
- CSV：回答データ原本（個別回答の公開範囲が未確認のため、公開用コピーではURLを省略）
- 回答数：3件
- 注意点：1件はUI/UXデザイナー兼採用担当という仮想ペルソナによる合成回答

### 実施したこと

1. 回答データを一覧で確認した
2. 選択式の回答数と割合を数えた
3. 5段階評価の平均値を確認した
4. 自由記述を意味の近いテーマに分類した
5. 複数回答に共通する問題を確認した
6. 事実・解釈・設計判断を分けて整理した
7. ユーザーの状況と影響を含む課題文に変換した
8. 影響と改善コストを考慮して優先順位を付けた
9. 課題をファーストビュー、作品ページ、リンク、文章量などの設計要件に変換した

### 得られた仮説

採用側は、最初に「この人は何ができるのか」「代表的な成果は何か」を知りたい。しかし、現在のサイトではその情報に短時間で到達しにくい。

### 振り返り

今回分かったのは、グラフは傾向を見つけるための道具であり、結論そのものではないということだった。回答数、評価、自由記述、ポートフォリオの目的を組み合わせて、初めて設計に使える仮説になる。

一方で、回答数が少なく、合成回答も含まれているため、現段階では確定的なユーザーニーズではなく、次の設計・検証で確かめる仮説として扱う。

### 次に行うこと

- 仮説を反映したファーストビュー案を作る
- 作品ページの情報構造を作る
- 改善案を見せて再評価を行う
- 実際の採用担当者から追加回答を集める
