# 分かったこと

## ユーザー調査・課題整理の目的

作り手が見せたい内容と、想定ユーザーが知りたい内容の差を明らかにする。今回の主な想定ユーザーは、UI/UXデザイン会社の面接官とエンジニア採用担当者である。

確認する内容は次のとおり。

- 最初に見たい情報は何か
- 採用判断に必要な情報は何か
- 制作物だけでなく、企画・要件定義・設計・改善の過程をどの程度見たいか
- キャラクターやアニメーションなどの個性が、理解を助けるか妨げるか
- 現在の要件に不足している情報や過剰な演出は何か

## 調査の流れ

1. 調査目的を決める
2. 調査対象・方法を決める
3. ユーザーの行動・ニーズ・判断基準を調べる
4. 回答を分析して課題を整理する
5. 課題に優先順位を付ける
6. 解決する課題を再定義する
7. 情報設計・ユーザーフロー・インタラクション設計へつなげる

## 今回の調査方法

知り合いのエンジニア・起業家にGoogleフォームで回答してもらう。回答時には、次の両方の視点を想定してもらう。

- エンジニアの視点：技術力、実装力、論理性、制作物の完成度
- デザイナーの視点：ユーザー視点、情報設計、体験設計、見せ方

質問は、第一印象、必要な情報、演出と使いやすさ、改善案を中心に、選択式と自由記述式を組み合わせる。

## ⚠️ 調査上の限界

今回の回答者は採用担当者本人の代表ではない。そのため、結果を採用担当者全体の意見として扱わない。

また、一人の回答者にデザイナーとエンジニアの両方の視点を想定してもらうため、実際の採用現場における複数職種の意見を完全に再現できるわけではない。両方の立場からの回答は、仮説を広げるための参考情報として扱う。

## 課題の優先順位付け

課題は、影響度・発生頻度・緊急度・実現可能性を基準に、優先度「高・中・低」で整理する。

- 高：理解や評価を大きく妨げるため、先に解決する
- 中：改善すると体験がよくなるため、余力があれば対応する
- 低：個人の好みや細かな調整に近く、後回しにする

## 次フェーズへの接続

調査後は、ファーストビューで伝える情報、情報の閲覧順、プロフィール・制作物・制作過程への導線、キャラクターや淡嶋AIの配置を情報設計・ユーザーフロー・インタラクション設計で決める。

現時点の仮説は、個性を残しながら、UI/UXデザイナーを目指していること、強み、代表作品、制作過程への導線を早い段階で示すことである。これは調査結果によって修正する。
