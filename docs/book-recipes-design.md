# 本制作レシピの設計・ヒアリング

## 目的

本人がチャットで回答すると、原稿・画像参照・表紙・ページ順・プレビューまで作れるようにする。会話の進捗を保存し、別チャットから再開できる構成にする。

## 確定した方針

2026-11-07、本人の「おk」で確認。

- 共通Skill portfolio-book-authoringからApps・Agents・Design・Internshipの4レシピを呼び分ける。
- 表紙・描画・検証・保存・本番反映の扱いは共通にし、レシピに複製しない。
- Apps・Designは、掲載する6項目を共通にする。目次＋作品について／課題・背景・目標／制作プロセス／検証・改善／成果と効果／使用技術・ツール。
- Agentsは最新回答により、作った経緯と使用後の変化を伝える4章。制作プロセス・使用技術の独立章は不要。
- カテゴリごとに、ヒアリングで深掘りする内容と文章へのまとめ方を分ける。
- Apps：利用者・機能・操作・実装の工夫。
- Agents：作る前の困りごと・きっかけ・試行錯誤・転機・使ってどう変わったか。
- Design：調査・デザインの判断理由・改善前後。
- Designの資料：ワイヤーフレーム／FigJamのユーザー調査／プロトタイプ／UI・ビジュアルデザインも載せる。画像＋解説＋元資料リンクを既存6章へ配置し、必要なら続きページを追加する。プロトタイプの操作は外部で開く。
- Internship：目次＋インターンについて／担当範囲／実際に行ったこと／工夫・判断／成果／振り返り。会社・期間・職種・参加理由は「インターンについて」にまとめる。

## 既存の確定事項

- 各社のインターン活動はHistoryのInternshipカテゴリ内の本で紹介する。別詳細ページや専用ナビを追加しない。
- 会社名・期間・職種、担当範囲、具体的な業務、関連制作、振り返りを収集する。
- 実績や数値を捏造せず、本人の担当と会社／チームの成果を分ける。未提供・掲載できない資料は制作記録に残す。
- 各本のintake.mdに回答・出典・省略理由・次の質問・進捗を保存する。
- 掲載内容は各項目1ページを優先するが、無理な縮小をせず必要なら分割する。

## 呼び出しと完了条件

このプロジェクトのチャットで「Appsの○○の本をヒアリングから作って」などと依頼する。既存資料を確認→不足だけ質問→回答を保存→表紙・本文を作成→参照検証とプレビュー→本人の修正、の順で進める。ユーザーによるファイル入力は必要ない。

レシピは全質問への回答を要求しない。核となる紹介内容が揃えば原稿を仕上げ、情報のない章を目次ごと省く。表示検証と本人確認が終わるまで完成扱いしない。原稿の確認と本番反映の依頼は別に扱う。
