# Historyの本：再構築方針

2026-11-06。ユーザーの見直し依頼を受け、Orchestrator・デザイン担当・3D担当・Reviewerが現コード、保存済みの静止／めくり途中画像、Works JP、詳細な3D Book設計書を確認した。今回は方針整理のみ。アプリコードは変更せず、ブラウザーの再検証もしていない。

## 今回の判断

本の内部は組み直す。現在の表示は品質確認に不合格として扱う。SkinnedMeshの導入、型チェック成功、ページ番号の変化だけを完成条件にしない。

- 技術は採用済みのThree.js・React Three Fiber・React Springを使う。
- 表紙は当面PNGなしの試作。黒い上製本の形・素材・陰影を先に作る。4枚のPNG原本は保持し、最終採否は後で確認する。
- 背景は採用済みの一体映像。Historyの本の背後・足元だけに柔らかい陰影を足し、映像と本を同じ画面として整える。
- 中央表紙は1回クリックで開く。Open bookボタンなし。ページはクリックと端からのドラッグでめくる。

## 現在の不具合と原因

| 確認した問題 | 再構築での対処 |
|---|---|
| 紙が動く開始時に前後位置が跳び、終了時に別の紙へ差し替わる | 紙ごとに固定IDを持たせ、表裏を持つ同じ紙を動かす |
| めくる紙と下敷きの紙に同じ本文が出る | 物理的な紙の表裏と本文番号を先に対応付ける |
| 静止紙と動く紙で明るさ・枠・文字配置が変わる | 共通の紙素材・本文レイアウトで描画する |
| 綴じ目・紙・表紙の原点と厚みが揃っていない | 綴じ目を共通原点にし、寸法と積層から配置する |
| めくり途中で紙がCanvasの上端に切れる | 変形途中を含む境界からカメラをフィットさせる |
| 閉じる状態でもopen=trueで、550ms後から閉じ始める | 実際のクローズ完了後にだけ画面移動を通知する |
| ドラッグ側と親側の両方がSpringへ命令する | Controllerが操作許可と進捗を一元管理する |
| 背景の明るい水平線と本が競合し、貼り付いて見える | 本の背後の局所的な暗さ・足元の影・輪郭の光を設計する |

確認箇所：`BookExperience.tsx`のVolume・close・turnSettled、`SkinnedPage.tsx`のfinishDrag・useSpring、`output/playwright/skinned-page-midturn.png`と`skinned-page-after-next.png`。これらは現状の証拠であり完成見本ではない。

## 見た目の共通案

宇宙映像の中に、黒い上製本を展示する。表紙はグラファイト系で微細な凹凸を持ち、背・表紙の厚み・黒い小口・綴じ目が光で読めるようにする。金枠だけで装飾する現在の表紙は最終デザインにしない。

閉じた本は少し斜めにし、表面と側面が同時に見える構図にする。中央本を主役に、隣の本は奥へ引く。上面とページ端が欠けないよう、ナビ・カテゴリ・操作バーを除く利用可能領域からサイズを決める。利用可能高の80〜85%は初期調整案であり確定値ではない。

本の背後の暗さは矩形の板として見せず、外周で透明になる柔らかい形にする。足元の影は映像内の地形を物理的に再現したものではなく、展示物をなじませる補助演出とする。暗い映像／明るい水平線／ループ中の全てで境界が目立たないことを確認する。

同一ファイルの同時編集は行わない。FrameEngine、背景WebP、scroll-preview、4画面のHTML UI、作品のTypeScript＋Markdownと4カテゴリ7作品の情報は再構築の基準として残す。試作リポジトリは骨格・UV等の参考に限定する。

物理的な紙をleaf 0、1、2…として登録する。初期見開きは左が内表紙、右がleaf 0の表。次は左がleaf 0の裏、右がleaf 1の表。同じleafの表裏テクスチャを途中で交換しない。めくり対象以外の紙は簡略化できるが、移動前後の形・本文・陰影を一致させる。

現在のSkinnedPageから参考に残すのは幅方向の分割・skinWeight・裏面UV・資源解放処理。新しいBookLeafは固定IDと外部の進捗を受ける描画部品にし、Springや入力を内部に重複して持たない。紙の表裏と周縁を共通骨で変形させ、静止・動作とも不透明な同じ材質を使う。

内部状態は`browsing → opening → reading → closing → returning → browsing`。readingの内部に`idle / dragging / settling`を持つ。ドラッグ開始時から他のページ操作を止め、進捗の所有者を一つにする。Springの完了と遷移IDを照合して確定し、固定時間だけで完了にしない。終了要求が来たらドラッグを解除して紙を有効な位置へ収め、表紙を閉じ、復帰完了後に一度だけ外部へ通知する。

## 実装の順番と合格条件

1. **背景上の閉じた単冊**：本体、背、黒い小口、表紙の凹凸、ライトと局所的な影を整える。厚みが見え、全四隅が収まり、背景に矩形の覆いが見えない。Designerが画像を確認する。
2. **単冊の開閉と紙のめくり**：右→湾曲→左、逆方向、ドラッグ途中の戻りを同じ紙で実現する。0／25／50／75／100%の状態を確認し、本文の重複、鏡文字、貫通、上下の欠け、完了時の跳びがない。動画または連続フレームと実操作で確認する。
3. **Historyへ統合**：4カテゴリ7冊、閉じた本の選択、背景ループ継続、読書中のホイール停止、閉じ終わってからナビ移動を確認する。連打、ドラッグ中の終了、リサイズで状態が壊れない。TesterとReviewerが確認する。

各段階の未達を残したまま次へ進めない。最初から全機能をつなぎ、後で見た目を直す進め方を改める。完成報告では画像・操作・状態・ビルドを区別する。

未確定なのは、最終表紙のPNG採否、具体的な素材値・カメラ値、正式本文とリンク、モバイルの詳細。今回の再構築方針の決定に追加画像は必要ない。

## 再構築版の実装記録

同日の実装指示を受けて以下を作成した。ユーザーによる最終的な見た目の承認はまだ受けていない。

- BookModel：面取りした表裏表紙、布のbump、背と溝、黒い小口。開いた背は紙の後ろへ下がる。
- BookLeaf：薄い厚み付きSkinnedMesh。固定ID・表裏の本文を保持し、同じ材質のまま湾曲する。長文でも紙束が表紙より前に出ないよう積層幅を制限する。
- BookExperience：操作とSpringを一元管理。ドラッグを端で開始、取消／確定し、めくり中のナビ要求を予約する。紙を収め、表紙のSpringが閉じ終えてから一度だけ親へ通知する。
- Stage：利用可能領域に合わせたサイズ、暖色のキーと弱い寒色の縁光、境界の見えない局所的な暗さと足元の柔らかい影。カルーセルの移動も補間する。
- textures：計測した改行とMarkdown段落ごとの紙面分割。正式作品の内容は仮本文のまま。

PCブラウザーの1440×900／1280×720で、前後送り、端のドラッグ確定／取り消し、末尾の制限、閲覧中のホイール停止、めくり中のナビが閉じ終わるまで待つこと、1冊・2冊・3冊のカテゴリ、リサイズを実操作した。ページエラーは0件。閉じた本、開いた本、めくり途中の画像も保存し、担当者が確認した。型チェック／本番ビルドは別途実行。
