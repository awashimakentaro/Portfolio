# スクロール動作確認サイト

現行実装の参考にした静的試作を保存したアーカイブです。本番はこのコードを読み込みません。映像原本は共通の `../../assets/frames/` を参照します。`待機.zip` の121枚を初回に自動再生する。待機、1、2、3の各終点では対応する `1-loop.zip`、`2-loop.zip`、`3-loop.zip`、`4-loop.zip`（各121枚）を繰り返す。次のスクロール操作を受けると、ループの現在の動きを約220msで次の区間の先頭へ重ねて切り替え、その区間のフレームは省略せず通常速度で自動再生する。上方向の操作では前の停止点まで逆再生する。再生中の入力は無視し、停止直後には250msの入力待ち時間を置く。各境界では次のZIPの1枚目を重複表示しない。画像は先にデコードしてCanvasへ描画する。既存のNext.jsフレーム確認アプリやポートフォリオ本体とは独立している。

1〜3-loopへ入る際は、前の区間の最終フレームからループの1枚目を表示し、それから2枚目へ進む。4-loopへ入る際は、4番目の本編（`3.zip`）の最終フレームから動き始めた4-loopへ220msでフェードする。

`4-loop.zip` の元画像は1940×1068で、他の系列（1916×1080）より横長。表示用の4-loop素材は左右を21pxずつ切り、1898×1068から1280×720へ縮小して縦横比を維持する。さらに3の最終フレームとキャラクター部分を比較して、4-loopの描画を約2.7%縮小し、位置をわずかに補正する。

4-loopは位置・倍率を合わせた1層だけを描く。共通の7%拡大で外周を埋める。

4-loopから本編へ逆に戻る場合は、従来の220msの切り替えを使う。

画面全体を埋めるため、すべてのフレームは `cover` 相当の倍率からさらに7%拡大して描画する。4-loopの縮小・位置補正後も余白が出ない倍率を基準にしている。画面の縦横比が素材と異なるときは、上下または左右の端を切って表示する。

起動：リポジトリ直下で `python3 -m http.server 8000 --bind 127.0.0.1` を実行し、`http://127.0.0.1:8000/archive/scroll-preview/` を開く。アーカイブのフォルダ単独で起動すると共通素材を取得できません。

素材：元の4系列と4つのループは各121枚。表示用WebPは `../../assets/frames/`（1280×720、品質68）。元PNGはZIPから再生成できるため、この確認用サイトには含めない。元ZIPは `/Users/制作物/UIUXメモ/05_ポートフォリオ/08_Webアプリ・3D演出実装/01_画面設計_Figma/最新/` にある。
