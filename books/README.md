# 本を作る場所

1冊ごとにフォルダを作り、作品情報・表紙・画像・ページ本文をまとめます。
まずは [Awashima Portfolio](design/awashima-portfolio/README.md) を完成見本として作ります。

## 質問に答えて作る

このプロジェクトを開いたCodexのチャットで、`$portfolio-book-authoring で〇〇の本を作って` と依頼できます。
別チャットでも `〇〇の本の続きを作って` と依頼し、必要ならSkill名を指定してください。回答と進捗は各本の `intake.md` に保存します。
既存資料を先に確認し、不足だけを質問してから、設定・画像参照・ページ本文を作り、Book Studioで確認する手順です。
Skill候補にまだ出ない場合は新しいチャットを開くか、`.agents/skills/portfolio-book-authoring/SKILL.md` を読んで進めるよう指定できます。
原稿プレビューを作るSkillであり、未実装の本番3D接続やデプロイが自動で済む機能ではありません。

## 最初に触るファイル

| やりたいこと | 編集する場所 |
|---|---|
| 本文を書く | 各作品の `pages/01.md` など |
| 写真・画面画像を追加する | 各作品の `images/` |
| 作品名・カテゴリ・Demo/GitHubリンクを変える | 各作品の `book.ts` |
| 表紙の装丁・画像・文字の見せ方を変える | 各作品の `cover.ts` |
| 未確定事項をメモする | 各作品の `notes.md` |

```text
books/
├─ apps/        pfc-tracker（Diet App） / campus-qiita / kodo / utd / presence-note
├─ agents/      engineer-learning
├─ design/      awashima-portfolio
├─ internship/  hr-cloud / pr-times / eyes-japan
├─ _templates/  project / agent / internship（新規複製用）
└─ types.ts     共通の設定項目
```

各本には `book.ts`、`cover.ts`、`intake.md`、`notes.md`、`pages/`、`images/` を置きます。既存7冊には、現在サイトで使っている仮本文を保持した `published.md` もあります。仮本文は確定した実績ではありません。


## 新しい本を増やす

このプロジェクトのCodexチャットで「Appsの本をヒアリングから作って」「Internshipの○○の続きを作って」と依頼できます。[共通Skill](../.agents/skills/portfolio-book-authoring/SKILL.md)が4カテゴリのレシピを選び、不足の質問から表紙・本文・プレビューまで作成します。回答と次の質問は各本のintake.mdへ保存します。以下のファイル操作はCodexが担当でき、ユーザーの手入力は必須ではありません。

1. Apps・Designは `_templates/project/`、Agentsは `_templates/agent/`、インターンは `_templates/internship/` を複製し、`<カテゴリ>/<作品id>/` に置きます。
2. `book.ts` の `id`（全作品で重複しない小文字の識別名）、`title`、`category` を変更します。
3. Demo/GitHub URLがあれば `links` に記入します。不明なリンクは未設定のままにします。
4. 画像を `images/` に置き、`cover.ts` とページ本文から参照します。
5. `pages/` の原稿を書きます。ページを増減したら `book.ts` の `pages` も更新します。
6. 内容・画像・見開きを確認してから、表紙・各ページ・本の `status` を `ready` にします。`ready` は確認済み原稿を意味し、公開操作ではありません。

フォルダは `category/id` と一致させます。idは作品の安定した識別子とし、カテゴリ変更時も維持します。カテゴリは `apps`・`agents`・`design`・`internship` の4つです。

確認できた基本情報は `book.ts` の `details`（summary・period・role・company）に任意で登録できます。未確認値を埋めず、本文の詳しい説明はMarkdownに記載します。

## ページと見開き

- **1つのMarkdown＝本文の1ページ（片面）**とします。文章量で勝手に次のページへ送りません。
- `book.ts` の `pages` に記載した順で並べます。ファイル名の並べ替えだけでは順番を変更しません。
- 制作プレビューでは01を左、02を右として、03／04、05／06と確認します。奇数ページの最後の相方は空白にします。
- この番号は本文の番号です。表紙は含めません。既存3D本の先頭・紙の表裏との対応は接続時に確認します。
- 章名は目次から上部ヘッダーに表示するため、本文で同じ大見出しを繰り返しません。必要なら別の小見出しを使います。画像は `![画像の説明](../images/profile.png)` のように、そのMarkdownからの相対パスで指定します。
- 紙面は `text`（文章中心）、`image-text`（画像と文章）、`statement`（大きなメッセージ）、`process`（番号付きの工程）から選べます。`book.ts` の各ページに指定します。
- `presentation` に `section`（ページの小見出し）、`callout`（大切な一文）、`facts`（ラベルと値の組）を必要な分だけ指定できます。内容をページ本文と二重登録しません。ページごとの色分けは廃止しました。
- 黒い装丁に合わせ、小見出しは淡いシャンパン色、本文は柔らかい青みのグレー、章ヘッダーは銀灰、リンクは控えめな金色で統一します。共通書体・余白・図解と、文字の役割による配色で読む順番を作ります。紙面上下のページ番号や単独の短い飾り線は付けません。ページの位置は紙面外の選択・前後操作で確認できます。
- 紙面内・プレビュー・画面全体にスクロール機能を設けません。画面内へ紙面を収め、PCは見開き、小画面は1ページずつ、ページ送りで読みます。
- 収まらない文章は、原稿を短くするかページを追加します。文字を際限なく小さくしません。

## 表紙

`book.ts` の作品名を使い、`cover.ts` に同じタイトルを二重入力しません。
黒い装丁は既存のカテゴリ共通PNGを参照します。装丁の原本を各作品フォルダへ複製する必要はありません。
`cover.ts` の画像パスは、その作品フォルダからの相対パスです。

## 原本と公開用データ

本の原本はこのフォルダへ集約しました。制作中の `pages/`・`cover.ts`・`links` と、現サイト向けの公開スナップショットを区別します。

- `pages/`・画像・`links`：Book Studioで確認する制作中の原稿。`ready`へ変更しても自動公開しません。
- `published.md`＋`publication.ts`：既存3Dのテキスト描画へ渡す明示的なスナップショット。現在は旧サイトの仮本文・表示順・装丁・リンクを保持しています。
- `npm run assets`（dev/buildの前にも実行）：`scripts/prepare-books.mjs`がpublication.tsのある本だけを選び、`public/book-content/`と`src/features/history/book/data/catalog.generated.json`へ出力します。これらの生成物を手編集しません。

新しい本にはpublication.tsを自動で追加しません。公開本文の差し替えは内容確認後に行います。従来形式の本は文章を自動分割します。fixed-pages指定では明示ページ・画像・目次と外部リンクを描画します。Studioの全紙面レイアウトの再現は別途必要です。制作原稿を単に結合してpublished.mdへコピーしても、Studioと同じ本にはなりません。

`intake.md`・`notes.md`・`references/`・制作中の画像はサイト生成物へ出しません。ただしGitHub上の閲覧可否はリポジトリ公開設定に従います。

## プレビューを開く

プロジェクト直下で次を実行します。制作プレビューにはNode.js 22.13以降が必要です（現在の開発環境では確認済み）。

```sh
npm run book:preview
```

[Book Studioを開く](http://127.0.0.1:3015/?folder=design%2Fawashima-portfolio)。HTMLファイルの直接表示ではなく、このURLを開きます。終了はターミナルでCtrl+Cです。
ポートを変える場合は `BOOK_PREVIEW_PORT=3016 npm run book:preview` を実行し、表示されたURLを開きます。

- 表紙／本文、ページ選択、前後ボタン・左右キーで表示を切り替えます。小画面では1ページずつ進み、PCでは見開きごとに進みます。画面サイズを変えても読んでいたページを保ちます。
- 文章・画像・設定を保存すると、約1.5秒間隔で更新を検知します。新しく複製した本も一覧に追加されます。
- 設定ミスがある場合は前の表示を残してエラーを表示します。ファイルを直すと復帰します。
- 拡大・スクロールの機能はありません。紙面比率を保って表示領域内へ収めます。
- はみ出す原稿は未完成として警告し、その紙面をエラー表示に置き換えます。隠れた本文を完成扱いせず、原稿の整理・ページ追加で解消します。自動改ページ・文字の自動縮小は行いません。
- Markdownは見出し・段落・箇条書き・単独行の画像・区切り線・引用（`>`）・太字（`**強調**`）・コード表記に対応します。HTMLやスクリプトは実行せず文字として表示します。表・埋め込み動画などは未対応です。
- 読み取り専用です。画面上の編集・公開操作はありません。ファイルをエディターで編集してください。

## 本番画面へ反映する操作

制作中のbook.ts・cover.ts・pagesは本番ビルドで読みません。公開用の作品名・カテゴリ・id・表示順・表紙URL・公開リンクは同じ本のpublication.tsに保存し、本文はpublished.mdに保存します。公開0冊のカテゴリは準備中表示になります。新規本はpublication.tsを作るまで本番一覧に入りません。ready指定だけでは公開しません。

Next起動中に公開用ファイルを更新した場合は、別ターミナルで `npm run book:sync` を実行し、ブラウザーを再読み込みします。これはローカルの生成処理で、push・デプロイは行いません。公開設定の書き間違いは本番生成で停止しますが、未公開の制作途中原稿のエラーはStudio側で扱います。

## 目次付きの作品集（固定紙面）

Apps・Designは目次→作品について→Context→制作プロセス→Review→Outcome→使用技術・ツールの6章を基本にします。目次のMarkdownは `[01　作品について](#about)` の形で、book.tsのページidを指します。外部リンクは `[Demoを開く](https://...)` を単独行に書きます。章は複数ページにできます。

Agentsは目次→このエージェントについて→作ったきっかけ→作りながら気づいたこと→使ってどう変わったかの4章。制作プロセス・技術一覧の章は設けず、本人の経験と変化を中心にします。Internshipは目次→インターンについて→担当範囲→実際に行ったこと→工夫・判断→成果→振り返り。Apps・Design・Internshipは目次＋6章の7ページ、Agentsは目次＋4章の5ページが初期テンプレートです。各章1ページを優先しつつ内容に合わせて増減します。Apps・Agents・Designは情報のない章を本文と目次から省きます。Internshipは上記6章の名前・順序を全社で固定し、未提供の章も目次と章ヘッダーを残して本文は空欄にします。レシピの決定内容は[本制作レシピの設計](../docs/book-recipes-design.md)にまとめています。

本番へこの原稿を反映する明示的な依頼があった場合は、次を順に実行します。

```sh
node scripts/snapshot-book.mjs design/awashima-portfolio
npm run book:sync
```

snapshotは検証したページ順・本文・表紙画像・URLをpublished.mdとpublication.tsへ書き出します。公開先が未作成の本は、先にpublication.tsのid・category・装丁・表示順を決めます。通常の原稿保存やStudio閲覧では実行しません。スナップショット後も本人未確認の制作statusはdraftを保ちます。

現在本番で描けるのは見出し・段落・画像・単独行の目次リンクと外部リンク。収まらない紙面はエラーにし、文章整理かページ追加で直します。旧10ページ案はPortfolioのreferences/previous-pagesに保存しました。写真の差し替え先は各本のimages/です。

## 表紙の固定枠と章ヘッダー

4種類の装丁にある上部の白枠内を、共通の画像配置領域とする。元画像1122×1402上の内側領域はx239・y199・幅699・高さ497。3Dでは透過余白の切り取り量から座標を変換し、Studioでは同じ元画像比率で配置する。写真は中央基準のcoverトリミングで枠を満たし、縦横比を維持する。設定はsrc/lib/book-layout.mjsに集約する。

固定紙面では目次の章名・順序から「01 作品について」「02 課題・背景・目標」等のランニングヘッダーを生成する。各章の両ページ・続きページに同じ章名を引き継ぎ、ページごとの見出しはその下に置く。ページ番号や単独の短い飾り線は追加しない。

## 英語表紙と紙の湾曲・文字

Portfolioの作品名は最新回答によりAwashima Portfolioへ変更。本文は自己配信のZen Kaku Gothic New Regularを使用し、フォントの準備後にCanvasへ描画する。本文テクスチャは論理寸法を保った1.5倍解像度で生成する。ネットワークでフォントを取得できない場合も本文は代替書体で表示する。

紙は背から中央・先端まで回転角を分布させ、中央のたわみと先端の追従遅れ、軽いねじれを加える。停止地点は平らに収束し、reduced-motionでは追従遅れを省く。通常のめくりはSpring、目次からの連続めくりは1枚440msで進める。進行中の閉じる・ナビ中断と操作ロックは維持する。

表紙リンクは文字・アイコン・背景と細枠をまとめた大きな丸いボタンとする。描画と判定範囲はcoverLinkRectsで共有する。本の制作Skillは表紙段階を独立させ、名称・画像・リンクの確認からプレビューと実画面の操作確認までを案内する。手順は.agents/skills/portfolio-book-authoring/references/cover.md。
